# 掌柜 Agent

> 新余恒太城大口章鱼烧的 AI 单店经营 Agent。

掌柜 Agent 当前不做加盟判断、不做通用餐饮 SaaS，也不替代客如云、美团、淘宝闪购或抖音后台。它只服务一个真实对象：

```text
新余恒太城五楼大口章鱼烧
```

目标是把线下店铺搬进系统，形成一个持续更新的数字模型，让老板通过说话、拍照、截图和上传资料，把真实经营信息喂给 Agent；Agent 自动识别、入库、建模、分析、预警，并用老板能听懂的话给出下一步动作。

## 产品目标

掌柜 Agent 的最高目标是：

```text
在食品安全、商场规则、员工可承受、顾客体验不崩的前提下，持续提高这家店的真实净利润。
```

第一目标是保住原店历史利润，第二目标是提升现金流和保本稳定性，第三目标是在风险可控的前提下冲击更高利润。

第一阶段的产品目标更窄：

```text
从今天开始，让新余恒太城五楼大口章鱼烧的钱账、库存、成本、利润变得可信。
```

第一阶段不追求复杂 Dashboard、多店管理、会员营销、供应链商城或完整员工绩效系统。当前最重要的是打通一条可靠闭环：

```text
老板上传资料
  -> Agent 识别资料类型
  -> 拆成销售事实 / 到账事实 / 采购事实 / 库存事实
  -> 发现缺口并追问
  -> 老板确认
  -> 入钱账或库存账
  -> 更新今日经营卡
```

## 使用方式

传统软件是：

```text
点菜单 -> 找表单 -> 填字段 -> 看报表 -> 自己判断
```

掌柜 Agent 是：

```text
说话/拍照/截图 -> Agent 识别 -> 用户确认 -> 自动入库 -> 自动分析 -> 主动给动作
```

## 产品调性

掌柜 Agent 可以参考 Matrix、Flowith Neo 这类产品的 Agent 运行思想，但不能仿造成“AI 公司后台”。

我们吸收的是：

- 长期目标驱动，而不是每次从零聊天。
- 专职 Agent 分工，而不是一个聊天框硬答所有问题。
- 每条建议都要有证据，而不是空口建议。
- 每天复盘更新，让模型越来越懂这家店。

我们自己的表达必须是小店老板能用的：

- 不叫 Matrix，叫掌柜总控台。
- 不叫 OKR，叫目标记忆。
- 不叫 Departments，叫掌柜分身。
- 不叫 Task Queue，叫今日推进。
- 不叫 Proof Shelf，叫证据架。

日常输入包括：

- 客如云日报截图
- 商品销量排行
- 美团/淘宝闪购/抖音后台截图
- 进货单
- 水电单
- 库存照片
- 总部资料
- 卫生/检查/培训资料
- 打烊异常和小票
- 老板口头记录

## 核心能力

### 第一阶段四个核心入口

- **掌柜台**：统一接收截图、照片、文字、语音和资料，输出今日经营卡、缺口追问和明天动作。
- **今日待确认**：所有 AI 抽取出的关键事实先进入待确认，老板确认、修改或驳回后才能写入。
- **钱账**：回答今天卖了多少、钱在哪里、哪些还在前老板账户、平台未结算和采购支出。
- **库存**：回答关键物料还够不够、今天入库/消耗/报损、明天要先补什么。

### 店铺数字模型

- 收入：客如云、堂食、外带、美团、淘宝闪购、抖音、退款、废单
- 成本：房租、商场费用、工资、水电、系统费、平台费、活动费、维修、罚款、转让费摊销
- 食材：章鱼粉、调味粉、章鱼粒、鸡蛋、酱类、海苔、木鱼花、蛤蜊、培根、蟹柳、小龙虾等
- 耗材：6 粒盒、4 粒盒、9 粒圆盒、塑料袋、打包袋、手套、纸巾、小票纸、封口贴、清洁用品
- 人员：员工、培训、熟练度、健康证、排班、离职风险
- 外部：天气、节假日、暑假/开学、商场活动、周边学校、小区、竞品、本地新闻

## 快速开始

### 后端

```bash
pip install -r requirements.txt
cp .env.example .env
python3 -m uvicorn server.main:app --port 8000
```

### 前端

```bash
cd web
npm install
npm run dev
```

默认前端端口是 `3005`。
