# 新余恒太城五楼大口章鱼烧｜仓管系统设计方案 v2

更新日期：2026-07-29  
文档状态：设计基线，待确认后实施  
适用对象：`xinyu-hengtai-dakou` 单店  

## 一、结论

仓管模块定位为：

> **一个高频的每日物料入口，配合低频的进货、库存、盘点和分析系统。**

它不是传统 ERP、WMS 或验货系统，也不围绕“叫菜”设计。门店每天只做一件高频动作：打烊后录入当天实际开封或领用的常用物料。老板按真实事件记录进货、到货、退款、报损和阶段盘点。

系统把这些事实连接为：

```text
固定物料 SKU
  → 采购来源与规格
  → 进货/到货/使用/报损/盘点事件
  → 总库存、成本和使用频率
  → 商品销量 × 已确认 BOM
  → 理论耗用、实际差异和毛利分析
  → Agent 解释、预警和行动建议
```

没有足够数据时，结果必须显示“资料不足”或“仅供校准”，不得用推测值冒充准确库存、损耗、毛利或补货日期。

## 二、本次对原方案的关键修订

### 1. 盘点范围不能继续写死为 52 项

当前门店主档实际为：

- 53 个活跃库存物料；
- 其中 35 个进入每日物料表；
- 其余 18 个只做阶段盘点；
- 22 个设备资产单独管理，不进入库存金额、物料耗用和补货预测；
- 总部目录中的未映射占位商品，不作为可盘库存。

因此产品不应把“35”“53”永久硬编码。应保存一份带生效日期的盘点范围版本；当前版本是 35 个每日物料和 53 个阶段盘点物料。以后增删真实 SKU 时，只更新范围版本，不破坏历史单据。

### 2. 删除未经确认的生产批次和 BOM 扣库

当前页面仍存在“半桶/一桶面糊生产批次”和固定配方文案。这些配方没有经过老板确认，与“每日开封/领用量”同时存在时还会重复扣减预拌粉、调料包。

实施第一优先级应是：

- 暂停生产批次自动扣库；
- 不显示任何未经确认的鸡蛋、水、海苔粉或其他单份用量；
- BOM 端口保留为空，由老板以后逐项录入并确认版本；
- BOM 未完整前，只分析实际每日使用和阶段盘点，不计算单品理论毛利。

### 3. 供应商应付只能有一个正式账源

库存负责“买了什么、到货多少、进入哪个 SKU、单位成本多少”；财务负责“形成多少应付、何时付款、从哪个账户付款、还欠多少”。

库存页面可以展示供应商应付摘要和对账视图，但不能另建一套独立应付账。付款操作必须写入财务账本，库存侧只读取结果。这样避免同一张配送单在仓管和财务各欠一次。

### 4. 库位准确度必须诚实表达

实际场景是老板从仓库拿货到店内，员工不负责去仓库，也不会记录调拨。系统不能在没有调拨记录的情况下宣称“仓库还有多少、店内还有多少”实时准确。

因此分两级管理：

- **全店总库存**：采购、每日使用、报损和阶段总盘共同影响，是主要经营口径；
- **库位库存**：只有老板记录“仓库补店”或完成分库位实盘后才是准确值，否则显示“上次实盘”或“估算”，并标注更新时间。

提供可选的“老板补店”快捷调拨，一次可填多个物料；不强迫员工记录，不影响全店总库存。

### 5. “收货”改为“到货入账”，不建设验货流程

门店没有罗森式验货收货需求。系统只需要记录事实：实际到了什么、多少、价格多少、是否退款或少货。前端统一使用“到货入账”，不增加验货人、审核人、签字或复杂状态。

### 6. Agent 的业务契约不绑定模型品牌

“能理解自然语言、能调工具、写入前确认、执行后回读”是产品要求；DeepSeek、Pi 或 Hermes 是可替换的技术实现，不应写成仓管业务事实。设计以能力契约和权限为准，模型或编排框架可独立升级。

### 7. 当前主账没有记录，不等于事实错误

门店资料可能先出现在其他对话、图片、纸质票据或线下表格里，之后才进入正式主账。审查时必须区分：

- **证据已提供**：已经存在原始图片、截图、Excel 或用户原话；
- **字段已提取**：系统或人工已经从证据中读取日期、商品、数量和金额；
- **用户已确认**：老板确认提取结果代表真实业务；
- **已写入主账**：已经映射固定 SKU 并形成正式业务单据；
- **已完成联动**：库存事件、成本、应付和付款结果均已回读核对。

不能因为某条事实尚未出现在 `store_facts.json` 或库存主账中，就直接判为错误或删除；也不能因为旧对话里出现过一段文字总结，就跳过原始证据复核直接入账。

## 三、真实门店执行 SOP

### 1. 每天打烊：每日物料使用

填写对象只包含当前 35 个常用物料，按营业动作分成：

- 基础粉料；
- 酱料；
- 撒料；
- 冷链配料；
- 餐盒与袋装；
- 出餐辅助耗材；
- 标签与收银耗材。

执行规则：

1. 选择营业日期；
2. 只填写当天实际开封或领用的整数；
3. 未使用项留空；
4. 不要求员工姓名和签字；
5. 报损另记，不混入正常使用；
6. 点击确认后，整天记录标记为“已完成”；
7. 同日再次保存为整日替换，冲销旧影响后写入新版，不能重复扣库；
8. 保存后回读当日单据、库存影响和事件编号。

纸质表和线上入口使用同一份范围版本、同一 SKU、同一单位和同一顺序。空白表示当天未用，但只有整张表确认后，系统才把这一天视为有效录入日。

### 2. 老板进货：订单与到货分开记录

#### 总部和网上平台

下单时保存：

- 下单日期；
- 平台、供应商或店铺；
- 外部订单号；
- 外部商品名称和规格；
- 对应固定物料 SKU；
- 订购数量、采购单位、单价、运费、优惠、实付；
- 原始截图或票据。

实际到货时再保存：

- 到货日期；
- 实到数量；
- 少货、退款或退货；
- 入库存放位置；
- 入库基础单位换算结果。

下单不增加库存；实际到货才增加库存。部分到货可以分多次入账。

#### 本地供应商

微信群叫货不要求建立订单。配送到店后，可从配送单直接创建“到货入账”：

- 配送日期；
- 供应商；
- 商品、实际重量或件数、当次单价和小计；
- 对应固定 SKU；
- 票据证据；
- 已付款或挂账。

蔬菜若确认当天全部使用，可使用“到货并直耗”快捷动作，同时生成到货和直耗事件；这不是默认假设。鸡蛋、油等留存物料正常进入库存。

当前跨任务证据中已确认一张尚未合并到正式主账的配送票据：

- 供应商：新余素源生态农业科技有限公司；
- 送达日期：2026-07-13；
- 鸡蛋：1 箱，¥237；
- 油：1 桶，¥165；
- 合计：¥402；
- 票据未证明已经付款，应按实际结账事实决定挂账状态；
- 鸡蛋每箱数量、油的品牌和容量仍缺失，因此先保存原采购单位，不擅自换算成“个”或“升”。

这条记录的状态应是“原始证据已复核、待正式入账”，不是错误数据，也不能因为尚未入账就参与当前库存余额计算。

另一张 2026-07-28 配送单进一步证明：叫货数量可以按“个/斤”等方式表达，实际结算按称重斤数和当次单价进行；供应商抬头也可能与历史名称不同。系统必须同时保留下单数量、实收数量、各自单位和原始抬头，并在用户确认前把供应商名称差异标为“主体/别名待核对”，不能自动合并。

### 3. 老板阶段盘点

阶段盘点不是固定周盘，可以在以下情况执行：

- 接店建立库存基线；
- 准备大批进货前；
- 月末或老板希望核对时；
- 账面与现场明显不符时；
- 需要校准补货模型时。

盘点表列出当前盘点范围版本中的全部活跃物料。老板分别填写仓库和店内/冰箱实盘，系统计算全店合计。盘点差异通过调整事件校准，不能直接覆盖历史余额。

### 4. 报损、退货和退款

- 损坏、过期、污染、掉落：报损事件，减少库存并记录原因；
- 已到货后退回供应商：退货事件，减少库存并同步减少应付或形成退款应收；
- 未到货订单退款：只更新订单和资金，不影响库存；
- 少货：按实到量入库，保留订购量与实到量差异。

## 四、产品信息架构

整个产品只保留一个“库存”一级入口，避免在全局侧边栏重复堆叠。库存模块内部采用三个稳定工作区：

| 工作区 | 频率 | 内容 |
|---|---:|---|
| 每日物料 | 每日一次 | 35 项快速录入、同日更正、当日记录回看 |
| 库存台账 | 低频按需 | 库存总账、进货与到货、盘点报损、采购来源、凭证 |
| 分析预警 | 事件/周期触发 | 使用趋势、库存风险、价格、差异、成本、报表、Agent |

库存台账内部二级页：

```text
/inventory/daily
/inventory/ledger/stock
/inventory/ledger/purchases
/inventory/ledger/counts
/inventory/ledger/suppliers
/inventory/ledger/evidence
/inventory/intelligence
```

供应商页展示采购价格和应付摘要；正式付款及资金账户仍跳转财务中心完成。

## 五、六层数据架构

### 第一层：统一主档

- 固定物料 SKU；
- 库存分类和营业动作分组；
- 基础计量单位；
- 每日使用范围版本；
- 阶段盘点范围版本；
- 仓库、门店、冰箱等位置；
- 供应商主档；
- 供应商法定名称、常用简称和票据抬头别名；
- 供应商商品、采购规格和单位换算；
- 安全库存、提前期和最小采购量；
- 设备资产独立主档。

同一物料只建立一个固定 SKU：

```text
固定 SKU
  ├─ 总部供应商品及规格
  ├─ 本地供应商品及规格
  └─ 网上平替商品及规格
```

供应商、包装规格和价格变化不创建重复 SKU。换算不明确时保留原采购单位，并显示“换算待补”，不伪造可用库存。

### 第二层：商品与 BOM 档案

这是原方案缺失的关键层：

- 门店标准商品；
- 规格/粒数/套餐等商品变体；
- 客如云及各外卖渠道商品名称映射；
- 生效日期明确的 BOM 版本；
- 每个 BOM 行对应固定物料 SKU、标准数量和单位；
- 包装物料同样进入 BOM；
- 未确认的 BOM 行不得参与扣库或毛利计算。

关系为：

```text
渠道销售明细
  → 标准商品/变体
  → 销售日期生效的已确认 BOM 版本
  → 理论物料耗用和理论成本
```

### 第三层：业务单据

- 每日使用单；
- 采购订单；
- 到货单；
- 当日直耗单；
- 报损单；
- 退货退款单；
- 盘点单；
- 库位调拨单；
- 财务侧供应商付款单引用。

每张业务单据还必须保存事实成熟度：证据已提供、字段已提取、用户已确认、已写入主账、已完成联动。只有“已写入主账”的单据产生库存或财务影响。

### 第四层：不可静默修改的库存事件

- 到货增加；
- 正常使用减少；
- 直耗减少；
- 报损减少；
- 供应商退货减少；
- 调拨一增一减；
- 盘盈、盘亏调整；
- 更正时冲销旧事件并建立新版本。

正式事件至少保留日期、单据、SKU、数量、单位、位置、证据和系统审计账号。日常录入界面不要求手填“操作人”。

### 第五层：财务共享事实

- 到货单提供库存资产数量和金额；
- 挂账到货在财务账本形成供应商应付；
- 付款只在财务账本减少应付和资金；
- 正常使用、直耗、报损和盘亏按成本规则进入经营成本分析；
- 采购付款不直接等于当期费用。

库存和财务共用同一业务单据 ID 与凭证 ID，任何一侧都不复制另一侧的正式账本。

### 第六层：指标、Agent 和报表

只从已确认单据、事件、财务事实和已确认 BOM 计算。每个结果都要显示周期、来源、更新时间、公式、可信状态、数据缺口和可追溯凭证。

## 六、库存与成本口径

### 1. 账面库存

```text
期末账面库存
= 期初库存
+ 到货
+ 调入
- 调出
- 正常使用
- 当日直耗
- 报损
- 供应商退货
± 盘点调整
```

全店总库存计算时，内部调拨一增一减相互抵消；分库位库存必须包含调入和调出。

### 2. 使用与差异

```text
记录正常使用 = 已确认每日使用单合计

全店实盘期间总减少
= 期初全店实盘 + 期间到货 - 供应商退货 - 期末全店实盘

未解释库存差异
= 全店实盘期间总减少 - 记录正常使用 - 当日直耗 - 明确报损

理论耗用
= 各标准商品/变体实销量 × 对应日期已确认 BOM
```

“未解释库存差异”和“实际对理论差异”必须分开：前者检查漏记、盘点误差或丢失；后者检查份量、BOM、销售映射和制作偏差。不能用一个“损耗率”混在一起。

### 3. 使用频率与补货

```text
日均使用 = 有效营业日的记录正常使用合计 ÷ 有效录入营业日
可用天数 = 当前可信总库存 ÷ 近期加权日均使用
建议采购量 = 目标覆盖期需求 + 安全库存 - 当前可用库存 - 已下单未到货
```

只有在当前库存可信、连续有效使用日足够、采购提前期和最小采购量齐全时才输出补货日期和数量。否则显示缺少哪些数据。

### 4. 成本和毛利

- 到货按基础单位换算后更新移动加权平均成本；
- 运费和订单级优惠必须有明确分摊规则，不能丢失；
- 正常使用、直耗、报损和盘亏按事件发生时的库存成本计价；
- 商品理论毛利 = 已确认商品收入－对应实销量的已确认 BOM 成本；
- 全店物料毛利 = 已确认营业收入－阶段实盘校准后的实际物料耗用成本；
- 渠道手续费、活动补贴、退款、人工、租金和水电不混进商品毛利，另用于贡献毛利和净利润。

BOM、渠道商品映射或阶段实盘不完整时，不显示精确单品毛利率。

## 七、Agent 设计

### 1. 能做什么

- 回答库存、进货、使用、价格、盘点、报损和应付摘要问题；
- 自动选择所需事实和计算工具，不依赖固定关键词；
- 识别票据并建议固定 SKU 映射；
- 找出同日重复、单位换算缺失、库存异常和价格变化；
- 解释为什么暂时不能算；
- 生成进货、到货、盘点或报损动作，并在用户确认后执行；
- 执行后回读单据、事件和余额，验证闭环。

### 2. 权限

- 查询和确定性计算可以直接执行；
- 建议不写入台账；
- 新增、修改、冲销正式单据必须就地确认；
- 不建立长期堆积的“待录入”页面；
- 不允许自动付款、自动下单或擅自修改价格/BOM。

### 3. 触发方式

- 每日只检查当日物料是否已经完整确认；
- 到货、报损、盘点、退款或付款后重新分析；
- 每周/月输出周期总结；
- 库存风险、价格突变、盘亏、应付逾期或数据断档时主动提醒；
- 没有新事实时保持安静。

## 八、分析页面

页面不是固定大屏，而是优先展示当前最值得处理的问题：

- 可信库存与数据完整度；
- 近 7/30 天使用趋势；
- 可用天数与补货资料完整性；
- SKU 采购价格趋势和供应来源比较；
- 已下单未到货；
- 盘点差异、报损和未解释差异；
- 理论与实际耗用差异；
- 商品销量、理论物料成本和毛利可信度；
- 供应商应付摘要与财务跳转；
- 今日最值得处理的一至三件事。

状态统一使用：

- **可信**：所需数据完整且已确认；
- **校准中**：存在记录，但当前实盘或连续使用不足；
- **估算**：明确展示假设、公式和误差来源；
- **不可计算**：列出阻塞字段，不返回貌似准确的数字。

## 十、必须通过的真实场景验收

1. 35 项每日使用能在几分钟内完成，未使用留空；
2. 同日重录只保留一个有效版本，不重复扣库；
3. 当前每日范围和总盘范围从同一 SKU 主档生成；
4. 总部多 SKU 订单可分多次到货；
5. 网上平替规格不同但映射到同一固定 SKU；
6. 本地配送单可直接到货入账并形成财务应付；
7. 一次付款可结多张配送单，一张配送单可分多次付款；
8. 未到货退款不动库存，已到货退货同时修正库存和财务往来；
9. 阶段盘点通过调整事件校准，不覆盖历史；
10. 老板未记录仓库补店时，全店总库存仍可计算，库位库存明确降级；
11. 未确认 BOM 不扣库、不显示单品精确毛利；
12. 商品销量、渠道映射、BOM、库存和财务可以沿同一业务日期追溯；
13. 所有金额与数量都能回到单据和原始凭证；
14. 数据不足时不输出虚假损耗、断货日或采购建议。
