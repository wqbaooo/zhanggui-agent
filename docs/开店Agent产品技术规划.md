# 开店 Agent 产品技术规划

## 1. 定位

这个项目要做的不是“资料问答机器人”，而是一个专精开店决策的创业顾问 Agent。

目标用户是想开餐饮、小吃、社区店、外卖店、饮品店、零售服务店的创业者。Agent 要帮助用户从“我想开店”推进到“能不能开、在哪开、开什么、花多少钱、怎么获客、怎么办证、何时止损”的完整决策链。

核心原则：

- 不给假大空建议，所有结论都要标注证据来源、假设和不确定性。
- 不用理想化模型骗用户，财务测算默认使用保守情境。
- 不把标题索引当作已读知识；视频必须转写，PDF 必须 OCR，才算进入知识库。
- 不越权抓取平台数据；地图、外卖、点评、小红书等数据优先走官方 API、授权数据或用户上传截图/表格。
- Agent 的价值不只是回答，而是追问、诊断、测算、规划、生成行动清单和阶段复盘。

## 2. 参考框架选择

建议主框架采用 LangGraph 思路：状态机 + 工具节点 + 人工确认。

原因：

- 开店规划是多阶段流程，适合拆成状态节点，而不是一次性聊天。
- 用户信息会逐步补齐，需要长期状态和项目档案。
- 需要调用多个工具：RAG、地图、财务模型、政策检索、平台数据、文档生成。
- 每个关键结论都应该能追溯证据，必要时让用户确认后继续。

可以借鉴 CrewAI 的“多角色 Agent”概念，但不建议一开始就把系统拆成复杂多智能体。先做一个可控主 Agent，内部挂多个专业工具/技能：

- 需求澄清器
- 资料检索器
- 商圈分析器
- 财务测算器
- 证照政策助手
- 营销开业助手
- 风险审查器

Dify 的 Knowledge/RAG Pipeline 思路适合借鉴资料处理：数据源 -> 抽取 -> 清洗 -> 切片 -> 向量化 -> 检索 -> 重排 -> 引用。

## 3. 用户旅程

### 阶段 A：开店画像建立

Agent 必须先问清楚：

- 城市、区域、候选商圈、候选铺位
- 品类：早餐、粉面、小吃、饮品、快餐、烘焙、社区便民等
- 预算、可承受亏损、是否借贷
- 自营/加盟/合伙/接转让店
- 用户经验：是否做过餐饮、是否懂后厨、是否有运营能力
- 时间投入：全职、兼职、雇人看店
- 目标：求稳养家、做副业、做连锁、做外卖、做堂食

输出：开店画像卡。

### 阶段 B：想法验证

Agent 对项目做可行性初筛：

- 需求是否刚需
- 复购是否成立
- 标准化程度
- 毛利空间
- 人工依赖
- 对选址依赖
- 外卖适配度
- 竞争强度
- 用户自身匹配度

输出：项目可行性评分、红黄绿灯、必须验证的问题。

### 阶段 C：选址与商圈分析

Agent 需要结合知识库和地图/POI 工具：

- 候选点 500m/1km 竞品密度
- 周边学校、写字楼、社区、医院、地铁、公交、商场、菜场等聚客点
- 动线：路过、停留、目的性消费、绕行成本
- 时间段客流：早、中、晚、工作日、周末
- 租金、转让费、面积、门头、可见性、排烟、明火、消防、外摆、停车
- 竞品评分、客单价、评论痛点、营业时间

输出：商圈诊断报告、铺位风险清单、蹲点采样表。

### 阶段 D：财务模型

Agent 必须能算：

- 初始投入：转让费、押金、租金、装修、设备、首批物料、证照、开业营销、备用金
- 月固定成本：租金、人力、社保、水电、物业、折旧、平台服务费
- 变动成本：食材、包材、配送、满减补贴、损耗
- 收入模型：日单量、客单价、堂食/外卖占比、毛利率
- 盈亏平衡：每天需要多少单才能不亏
- 回本周期：保守/基准/乐观三套情境
- 止损线：连续几个月达不到什么指标必须调整或关停

输出：开店财务测算表、敏感性分析、止损阈值。

### 阶段 E：证照与合规

餐饮类至少要覆盖：

- 营业执照
- 食品经营许可或地方小餐饮许可
- 从业人员健康证明
- 消防、燃气、环保、排烟、外摆、招牌等地方要求
- 网络餐饮平台入驻资料
- 原料采购索证索票、台账、食品安全制度

输出：按城市/区县生成办证清单和材料清单。政策必须联网查最新官方来源。

### 阶段 F：开业准备与运营

Agent 需要生成：

- 菜单结构
- SKU 毛利表
- 设备耗材清单
- 人员排班
- SOP：采购、备餐、出餐、清洁、收银、外卖打包、差评处理
- 试营业计划
- 开业活动
- 抖音/小红书/团购/达人推广方案
- 30/60/90 天复盘指标

输出：开业作战计划。

## 4. Agent 架构

推荐状态图：

1. IntentRouter：识别用户意图和阶段
2. ProfileCollector：抽取并补齐开店画像
3. KnowledgeRetriever：从勇哥视频、PDF、通用知识库、政策库检索
4. MarketDataTool：地图/POI/竞品/平台数据采集
5. FinanceTool：成本、利润、现金流、盈亏平衡测算
6. RiskCritic：从反方角度审查：为什么这个店可能亏
7. Planner：生成阶段性方案和下一步动作
8. EvidenceReporter：列证据、假设、不确定性、需要用户实地验证的事项
9. MemoryWriter：把用户项目档案、候选铺位、测算版本保存下来

关键设计：

- 每次回答都要区分：事实、推断、假设、建议。
- 高风险决策必须触发 RiskCritic。
- 没有真实数据时只能给“采样方案”，不能伪造结论。
- 所有外部数据保留采集时间和来源。

## 5. RAG / Skill 知识库设计

知识源分层：

- S1：勇哥视频完整转写稿、课程结构、关键方法论
- S2：PDF/OCR 文档，尤其是餐饮选址实用指南
- S3：开店通用知识：选址、财务、办证、运营、营销
- S4：政策库：国家政策 + 地方政务服务页面
- S5：项目档案：用户自己的城市、预算、铺位、竞品、测算结果
- S6：实时外部数据：地图 POI、用户上传平台截图、平台授权 API

检索策略：

- 混合检索：关键词 BM25 + 向量检索
- 元数据过滤：品类、城市、阶段、资料类型、可信等级
- 重排：优先完整转写/官方政策/用户实采数据
- 引用：每条建议后面可追溯到 chunk/source/page/video/time

视频入库标准：

- 每个视频生成 transcript
- 分段保留时间戳
- 提取：摘要、要点、行动建议、风险提醒、适用品类、适用阶段
- 未转写的视频只能作为目录，不能作为证据

PDF 入库标准：

- 可抽文本 PDF：直接切片
- 扫描 PDF：OCR 后切片
- 保留页码和原图位置
- 对表格、流程图、清单单独结构化

Skill 设计：

- `选址分析.skill`
- `财务测算.skill`
- `办证合规.skill`
- `外卖平台分析.skill`
- `开业营销.skill`
- `风险审查.skill`
- `复盘诊断.skill`

## 6. 工具与数据能力

### 多模态线下场景分析

开店 Agent 必须具备图片/视频理解能力，因为线下选址判断里大量信息来自现场画面，而不是文字。

典型输入：

- 用户上传店铺门头照片
- 用户上传门前街景、左右邻铺、对面街景
- 用户上传 360 度环拍视频
- 用户上传商场楼层动线、街区转角、地铁口出口、停车场入口照片
- 用户上传美团/小红书/地图截图

视觉分析目标：

- 门头是否清晰可见，是否被树、车、灯箱、围挡、立柱遮挡
- 主客流方向是否能看到门头
- 是否有台阶、围栏、绿化带、停车位、隔离栏影响易接近度
- 是否临近聚客点：社区门口、学校、写字楼、医院、菜场、公交/地铁口
- 周边店铺类型是否与目标品类匹配
- 是否存在明显硬伤：门宽过窄、采光差、无排烟位置、门前施工、招牌空间不足
- 画面中的竞品、价格牌、客流状态、停车状态、外卖骑手停靠情况

建议实现为 `VisionSceneAnalyzer` 工具，而不是直接让主 Agent 随意看图。

输出结构：

```json
{
  "scene_type": "店铺门头/街景/室内/地图截图/平台截图",
  "observations": [
    "门头被树冠遮挡约30%",
    "门前有两级台阶",
    "右侧为便利店，左侧为空铺"
  ],
  "risks": [
    "主客流方向识别度不足",
    "易接近度下降"
  ],
  "questions": [
    "请补拍从主客流方向20米外看门头的照片",
    "请补拍门口左右各45度角照片"
  ],
  "scores": {
    "visibility": 60,
    "accessibility": 55,
    "traffic_signal": 70,
    "category_fit": 65
  },
  "evidence": [
    {
      "type": "image_region",
      "description": "门头上方被树叶遮挡",
      "confidence": "medium"
    }
  ]
}
```

视频处理策略：

- 用户上传 360 度视频时，先抽关键帧，不把整段视频直接塞给模型。
- 按时间点抽帧：0s、3s、6s、9s，或按画面变化抽帧。
- 对关键帧做视觉描述、OCR、风险识别。
- 把视觉结论和用户口述、地图数据、财务模型合并判断。

重要原则：

- 视觉模型只做“可见事实”和“风险线索”，不能单独拍板。
- 需要结合用户补充信息：租金、面积、品类、日客流、竞品、证照条件。
- 视觉判断必须要求用户补拍缺失角度，尤其是勇哥常说的“360 度看商圈”。

### 地图能力

优先接入：

- 高德地图/百度地图：中国大陆 POI、周边检索、地理编码、路线、商圈竞品
- Google Places：海外场景或补充数据

可做功能：

- 候选地址转经纬度
- 500m/1km 周边 POI
- 同品类竞品密度
- 交通点/学校/社区/写字楼/医院/商场聚客点
- 路线可达性和门前动线辅助判断

### 外卖/点评/小红书能力

要谨慎处理：

- 美团、饿了么、小红书很多数据没有通用公开接口，不能默认非法抓取。
- 可先支持用户上传截图、CSV、手工记录，Agent 做结构化分析。
- 有授权 API 时再做自动接入。
- 对平台数据标注采集方式，避免误导。

可分析字段：

- 竞品名称、评分、月售、客单价、套餐、满减、配送费、评论关键词、差评原因
- SKU 结构、爆品、价格带、营业时间
- 外卖毛利：平台佣金、配送、包材、满减、活动补贴

### 财务能力

先做确定性计算，不依赖 LLM：

- 盈亏平衡单量
- 月现金流
- 回本周期
- 租金营收比
- 毛利敏感性
- 日单量敏感性
- 堂食/外卖比例敏感性

LLM 负责解释和策略，不负责裸算。

## 8. 分阶段路线图

### V1：可信知识库与规划骨架

- DeepSeek 通过环境变量接入
- PDF OCR 入库
- 162 个视频转写入库
- 建立混合检索和引用机制
- 把当前状态机升级为明确节点日志
- 每次回答展示：证据、假设、风险、不确定性

### V2：开店画像 + 财务测算

- 项目档案保存
- 财务模型模块
- 盈亏平衡、回本周期、敏感性分析
- 输出 Excel/Markdown 报告
- 风险审查器

### V3：地图与竞品分析

- 高德/百度地图接入
- 地址解析、周边 POI、竞品密度
- 候选铺位评分
- 实地蹲点采样表

### V4：平台数据分析

- 用户上传美团/饿了么/小红书截图或 CSV
- OCR/结构化提取
- 竞品价格、月售、评论痛点、活动策略分析
- 外卖毛利模型

### V5：开业执行系统

- 办证政策联网检索
- SOP、设备耗材、人员排班
- 30/60/90 天复盘
- 项目看板和历史方案对比

### V6：多模态现场诊断

- 支持用户上传店铺照片
- 支持用户上传 360 度环拍视频
- 自动抽关键帧
- 对门头、动线、遮挡、台阶、停车、聚客点、竞品做视觉诊断
- 生成补拍清单和现场蹲点表
- 把视觉证据写入项目档案和 RAG 记忆

### V7：接入个人总助理 Agent

开店 Agent 未来应该作为“个人总助理 Agent”的一个垂直技能，而不是孤立系统。

接入方式：

```text
个人总助理 Agent
├── 日程/文件/电脑管理能力
├── 通用规划能力
├── 开店 Agent Skill
│   ├── 开店画像
│   ├── 商圈选址
│   ├── 财务测算
│   ├── 办证合规
│   ├── 多模态现场诊断
│   └── 开业运营
└── 其他垂直 Skill
```

边界设计：

- 总助理负责理解用户的大目标、调度任务、管理文件、提醒、日程和跨项目协调。
- 开店 Agent 负责开店领域的专业判断，不直接控制用户电脑或乱调用外部工具。
- 开店 Agent 输出结构化结果，交给总助理保存、排期、提醒、生成文档。

推荐接口：

```json
{
  "skill_name": "store_opening_agent",
  "input": {
    "task": "评估候选铺位",
    "project_id": "hangzhou_breakfast_001",
    "user_profile": {},
    "attachments": [],
    "constraints": {}
  },
  "output": {
    "summary": "",
    "decision": "go/no-go/needs_more_data",
    "risks": [],
    "next_actions": [],
    "artifacts": [],
    "memory_updates": {}
  }
}
```

这样以后总助理可以说：

- “把这个铺位评估交给开店 Agent”
- “把开店 Agent 的财务表放进项目文件夹”
- “提醒我周六早上去蹲点”
- “把这几张门头照片加入杭州早餐店项目”

开店 Agent 的知识库和项目记忆必须独立保存，但通过标准接口被总助理调用。
