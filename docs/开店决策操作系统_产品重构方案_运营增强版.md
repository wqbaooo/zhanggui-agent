> 版本：v1.0  
> 目标读者：OpenCode / Codex / Claude Code / 产品设计与开发执行者  
> 产品方向：开店决策 + 加盟反套路 + 投资测算 + 选址判断 + 开店后运营驾驶舱

---

## 0. 回答你的问题：是否结合了之前沉淀的分析？

是的，这份方案不是单纯临时拼出来的页面清单，而是结合了前面多轮讨论里已经形成的几个关键判断：

1. **产品不能只是“加盟测算器”**  
   之前已经判断过，加盟只是开店链路里的一个阶段。真正的产品应该覆盖“加盟前决策”和“开店后盈利运营”两个连续阶段。

2. **加盟不是简单的好/坏判断，而是信息不对称问题**  
   品牌方掌握招商话术、合同条款、样板店数据、供应链价格、闭店率等信息；小白创业者掌握的信息很少。所以产品核心应该是“拆话术、拆费用、拆合同、拆经营假设”。

3. **产品要从聊天工具变成结构化 AgentOS**  
   我们前面反复讨论过，你不想要一个普通聊天页，而是要一个卡片式、驾驶舱式、结构化的产品。AI 可以在后台，但用户前台看到的应该是指标、风险、证据、动作清单，而不是“你问一句我答一句”。

4. **首页必须是风险总览，而不是欢迎页**  
   之前已经明确：用户打开产品要立刻知道“这个店现在最危险的地方在哪里”。所以首页应该是项目体检 Dashboard。

5. **风险清单是中枢，不是附属页面**  
   加盟分析、投资测算、选址判断、运营驾驶舱产生的所有风险，都要沉淀到统一 Risk Register。这样产品才像一个决策操作系统，而不是几个孤立工具。

6. **OpenCode/Codex 执行要以可运行交付为目标**  
   前面已经出现过“观察 7 天”这种错误方向，所以这份文档明确要求：不要观察、不要只建议、不要停留在计划，必须直接改代码、建模块、跑检查、输出结果。

## 1. 产品一句话定义

这个产品不是“加盟测算器”，也不是“开店记账本”，而是一个面向小白创业者、小微门店老板、加盟意向者的：

> **开店决策 + 加盟反套路 + 盈利运营一体化 AgentOS。**

它要解决的不是“用户填几个数字，系统算一下能不能赚钱”这么简单的问题，而是要把开店过程中最容易失控的三件事统一起来：

1. **加盟前的信息不对称**  
   品牌方掌握话术、合同、案例、供应链、样板店数据，创业者只看到招商宣传。

2. **开店前的财务误判**  
   很多人只算加盟费、装修费、设备费，却没有认真算保本订单数、现金流安全月数、最差情境亏损。

3. **开店后的经营失控**  
   开业后真正决定生死的是日营业额、毛利、人工、房租、复购、损耗、平台抽佣，而不是招商 PPT 里的回本故事。

所以这个产品的核心不是“帮用户乐观决策”，而是：

> **用结构化数据、风险规则、经营模型，把一个门店项目从冲动投资变成可验证决策。**

## 2. 外部依据与产品判断基础

### 2.1 商业特许经营不是单纯销售行为

在中国商业特许经营语境里，特许人通常需要具备成熟经营模式，并具备持续经营指导、技术支持和业务培训能力。公开政策解读中也提到，“两店一年”通常被用于衡量成熟经营模式，即特许人应拥有至少 2 个直营店，并且经营时间超过 1 年。参考资料：上海市商务委相关解读：https://sww.sh.gov.cn/assets/RECP/y_05.html

这意味着产品里的加盟分析不能只问“加盟费多少”，还要问：

- 品牌是否具备成熟经营模式？
- 是否有真实直营店？
- 直营店经营时间是否足够？
- 是否提供持续经营指导？
- 是否具备真实可复制的运营体系？

### 2.2 财务承诺必须回到证据

FTC Franchise Rule 及相关解释中强调，特许经营销售方如作出财务表现陈述，需要具备合理基础和书面支撑。参考资料：FTC Franchise Rule：https://www.ftc.gov/legal-library/browse/rules/franchise-rule 以及 eCFR 16 CFR Part 436：https://www.ecfr.gov/current/title-16/chapter-I/subchapter-D/part-436

这可以转化为产品规则：

- 品牌方承诺“几个月回本”，必须追问样本来源。
- 品牌方给出“平均营业额”，必须追问城市、店型、租金、面积、人工、毛利。
- 品牌方只展示成功案例，不展示亏损样本，应计入风险。
- 如果承诺没有写入合同或披露材料，不能被当成可靠事实。

### 2.3 开店测算的核心是保本点

美国 SBA 对 break-even point 的解释是：当总成本和总收入相等时，企业没有盈利也没有亏损。参考资料：https://www.sba.gov/business-guide/plan-your-business/calculate-your-startup-costs/break-even-point

所以投资测算模块不应该只显示“预计利润”，而必须显示：

- 日均保本营业额
- 日均保本订单数
- 月固定成本
- 贡献毛利率
- 回本周期
- 现金流安全月数

### 2.4 餐饮和门店经营要看 prime cost

餐饮行业常用 prime cost 表示原材料/销货成本 + 人工成本。Restaurant365 对 prime cost 的定义是 COGS + Labor Costs；NOVA 2026 年文章提到，prime cost 常见 benchmark 约为销售额的 60%-65%，但会因服务类型变化。参考资料：Restaurant365：https://www.restaurant365.com/blog/how-to-calculate-prime-cost-in-a-restaurant/ ，NOVA：https://www.novatab.com/blog/restaurant-prime-cost

这可以转化为运营驾驶舱规则：

- 原材料 + 人工占比过高，利润会被压缩。
- 外卖抽佣、营销补贴、损耗也要进入真实利润判断。
- 不要只看流水，要看扣除关键成本后的经营健康度。

## 3. 产品总目标

## 3.1 业务目标

把产品做成一个**小白开店前后的决策驾驶舱**。

它要帮助用户完成：

1. 判断一个加盟品牌是否值得继续谈。
2. 判断一个门店投资模型是否能撑住。
3. 判断一个选址是否值得实地蹲点。
4. 判断开业后每天的经营是否偏离保本线。
5. 判断当下最该处理的问题是什么。
6. 把所有风险沉淀成一个持续更新的 Risk Register。

## 3.2 产品不是

这个产品不要做成：

- 普通 AI 聊天页
- 加盟项目展示平台
- 招商广告平台
- 纯记账工具
- 财务软件
- Excel 计算器外壳
- 只会输出“建议谨慎”的假分析系统

## 3.3 产品应该是

它应该像：

- 一个开店军师
- 一个加盟尽调助手
- 一个门店财务体检工具
- 一个小型运营驾驶舱
- 一个持续更新的风险台账
- 一个能把冲动创业降温的决策系统

## 4. 核心用户画像

## 4.1 加盟意向者

典型状态：

- 看到某个品牌很火
- 被招商人员持续跟进
- 手里有 10 万到 80 万预算
- 不懂合同、不懂毛利、不懂选址
- 容易被“总部扶持”“快速回本”“保姆式开店”吸引
- 不知道该问品牌方什么问题

他们需要的是：

> 帮我看这个品牌是不是坑，帮我知道下一轮该问什么。

## 4.2 准备开独立小店的人

典型状态：

- 不一定加盟
- 想做奶茶、小吃、咖啡、社区零售、轻餐、烘焙、美甲、宠物店等
- 对选址、租金、装修、保本营业额没有系统认知
- 容易低估启动成本和现金流压力

他们需要的是：

> 帮我算清楚这家店到底要卖多少才不亏。

## 4.3 已经开店的人

典型状态：

- 已经营业
- 每天有流水，但不知道到底赚不赚钱
- 外卖平台抽佣、人工、房租、损耗不断吃掉利润
- 不知道问题出在客单价、客流、毛利、复购还是成本结构

他们需要的是：

> 告诉我今天经营哪里不健康，下一步先改什么。

## 5. 产品主流程

```txt
用户产生开店想法
        ↓
录入项目基本信息
        ↓
拆解品牌方承诺
        ↓
识别加盟风险
        ↓
录入投资成本
        ↓
计算保本线和回本周期
        ↓
评估选址假设
        ↓
生成待验证问题
        ↓
开店后持续记录经营数据
        ↓
系统监控偏差并给出下一步动作
```

这个产品最重要的差异化是：

> **它不把品牌方宣传当事实，而是把所有输入都当成“待验证假设”。**

## 6. 产品信息架构

主导航建议设计为 7 个一级模块：

```txt
1. 总览 Dashboard
2. 加盟分析 Franchise Analysis
3. 投资测算 Investment Model
4. 选址判断 Location Assessment
5. 运营驾驶舱 Operations
6. 风险清单 Risk Register
7. 反馈 Feedback
```

每个模块都不是孤立页面，而是共同服务一个项目对象。

核心数据关系：

```txt
Project
 ├─ FranchiseAnalysis
 ├─ InvestmentModel
 ├─ LocationAssessment
 ├─ OperationDailyRecords[]
 ├─ RiskItems[]
 └─ FeedbackItems[]
```

用户不是在不同工具之间跳转，而是在围绕同一个“门店项目”持续补全信息。

# 7. 模块一：首页 Dashboard

## 7.1 首页定位

首页不是欢迎页，不是营销页，不是空洞的“你好，今天想做什么”。

首页要回答一个问题：

> **这个开店项目现在最危险的地方是什么？**

用户一打开产品，应该看到当前项目的健康状态，而不是看到一个聊天框。

## 7.2 首页结构

### 区域 A：项目状态栏

展示：

```txt
项目名称：XX 奶茶加盟项目
行业：新茶饮 / 小吃 / 咖啡 / 零售 / 服务业
阶段：想法期 / 洽谈期 / 选址期 / 装修期 / 试营业 / 正式经营
预算：¥300,000
当前风险等级：高
最近更新时间：2026-05-29
```

阶段很重要，因为不同阶段的风险不同。

例如：

- 想法期：重点是品类和品牌判断
- 洽谈期：重点是合同、费用、承诺、披露资料
- 选址期：重点是租金、人流、竞品和保本订单数
- 装修期：重点是预算超支和现金流
- 试营业：重点是真实流水和预期偏差
- 正式经营：重点是利润、复购、损耗和成本结构

### 区域 B：四个核心指标卡

```txt
[总风险评分] [预计回本周期] [日均保本订单数] [现金流安全月数]
```

每张卡片不能只显示数字，必须显示解释。

示例：

```txt
总风险评分：78 / 100，高风险
原因：品牌信息披露不足、回本周期过长、保本订单数偏高。

预计回本周期：19.6 个月
原因：初始投资 42 万，月净利润中性预测约 2.1 万。

日均保本订单数：164 单
原因：月固定成本 6.8 万，客单价 28 元，毛利率 52%。

现金流安全月数：4.3 个月
原因：若试营业期月亏损 1.8 万，当前备用现金可支撑约 4.3 个月。
```

### 区域 C：最大风险诊断

这个区域应该像咨询报告里的“Executive Risk Summary”。

展示 3 个当前最重要的风险。

示例：

```txt
当前最大风险 1：品牌方承诺回本，但没有提供可验证门店流水
严重程度：高
影响：用户可能基于不可验证数据签约
建议动作：要求品牌方提供近 6 个月不同城市、不同店型的真实经营数据

当前最大风险 2：日均保本订单数过高
严重程度：高
影响：门店需要每天 160+ 单才能覆盖固定成本
建议动作：实地蹲点目标点位，统计工作日和周末真实客流

当前最大风险 3：强制采购比例不明
严重程度：中高
影响：后续毛利率可能被总部供货价锁死
建议动作：要求品牌方提供完整物料采购价目表
```

### 区域 D：今日建议动作

首页不能只告诉用户“你有风险”，还要告诉用户今天做什么。

示例：

```txt
今日最该做的 3 件事：

1. 向品牌方索要完整费用清单，包括保证金返还条件、设备采购价、首批物料明细。
2. 到目标铺位蹲点 2 小时，记录进店人数、经过人数、竞品客流。
3. 把客单价下调 15%、订单数下调 25%，重新查看最差情境回本周期。
```

### 区域 E：待验证问题清单

所有没有被证据确认的信息，都进入待验证问题清单。

示例：

```txt
待验证：
- 品牌方所说“6-8 个月回本”是否有真实样本？
- 目标点位日均自然客流是否足够支撑 160 单？
- 总部物料采购价是否高于市场价？
- 合同是否允许提前退出？
- 加盟区域是否有保护？
```

# 8. 模块二：加盟分析

## 8.1 模块定位

加盟分析不是让用户填“加盟费多少”然后给一个分数。

它应该做的是：

> **拆解品牌方的招商话术、费用结构、合同义务、经营承诺和信息透明度。**

产品态度应该是：

- 不预设品牌方是骗子
- 也不预设品牌方可信
- 所有承诺必须回到证据
- 所有费用必须回到现金流
- 所有合同义务必须回到经营自由度

## 8.2 输入结构

### A. 品牌基础信息

```txt
品牌名称
所属品类
成立时间
开放加盟时间
直营店数量
加盟店数量
是否可查询备案
是否有注册商标
是否有成熟运营手册
是否提供培训
是否提供持续督导
```

### B. 费用结构

```txt
加盟费
保证金
品牌使用费
管理费
培训费
设计费
设备费
装修费
首批物料费
系统使用费
营销费
平台服务费
年度续约费
其他强制费用
```

每一项费用都要标记：

```txt
金额
是否一次性
是否可退
是否强制
是否总部指定
是否有明细
是否高于市场价
证据来源
```

### C. 合同与权利义务

```txt
合同年限
是否有冷静期
是否可单方解除
保证金返还条件
违约金规则
区域保护范围
是否允许转让
是否允许自主采购
是否必须参加总部活动
总部是否可单方面调整规则
总部是否有最低采购要求
```

### D. 经营承诺

```txt
品牌方是否承诺回本周期
是否承诺营业额
是否承诺毛利率
是否承诺选址成功率
是否提供真实门店流水
是否允许联系老加盟商
是否提供闭店率
是否提供同城竞店数据
是否提供亏损门店案例
```

## 8.3 输出结构

### 结果 1：品牌风险等级

```txt
品牌风险等级：高
综合评分：73 / 100

主要扣分原因：
- 未提供真实门店流水
- 不允许联系老加盟商
- 强制采购价格不透明
- 合同退出机制不明确
- 承诺 6 个月回本但无样本依据
```

### 结果 2：招商话术识别

系统识别常见话术：

```txt
话术：总部全程扶持
风险解释：需要进一步确认扶持内容是选址、培训、督导、营销，还是仅提供开业物料。

话术：小投资高回报
风险解释：需要拆解完整初始投资和最差情境现金流，不能只看加盟费。

话术：最快 3 个月回本
风险解释：必须要求品牌方提供样本门店数据，包括城市、面积、租金、营业额、毛利、人工、开业时间。

话术：区域保护
风险解释：需要确认保护半径、线上外卖是否算冲突、商场店和街边店是否互斥。

话术：统一供应链
风险解释：需要确认采购价、毛利空间、是否允许替代采购、涨价机制。
```

### 结果 3：隐藏成本提示

```txt
可能隐藏成本：
- 二次装修成本
- 总部指定设备溢价
- 首批物料压货
- 开业营销强制投入
- 系统使用费
- 品牌年度管理费
- 续约费
- 物料物流费
- 平台活动补贴
- 总部新品物料强制采购
```

### 结果 4：合同风险点

```txt
合同风险：
- 保证金返还条件不明确
- 总部有单方面调整采购价格权利
- 区域保护范围模糊
- 加盟商提前退出违约金过高
- 总部承诺没有写入合同
- 闭店后设备、物料、装修残值无法处理
```

### 结果 5：继续谈判建议

```txt
建议：暂缓签约，继续尽调

原因：
1. 当前品牌方承诺多，但证据不足。
2. 投资模型对订单数高度敏感。
3. 强制采购可能压缩毛利。
4. 合同退出条款不清晰。

下一步：
- 不要交定金
- 不要签意向书
- 要求提供完整合同文本
```

# 9. 模块三：投资测算

## 9.1 模块定位

投资测算不是“预计能赚多少钱”，而是要判断：

> **这个项目在保守情境下会不会把用户拖死。**

它的重点不是乐观利润，而是：

- 日均保本订单数
- 回本周期
- 现金流安全月数
- 最差情境亏损
- 对关键变量的敏感性

## 9.2 输入字段

## 9.3 计算公式

### 初始投资总额

```txt
初始投资总额 =
加盟费
+ 保证金
+ 转让费
+ 房租押金
+ 首月房租
+ 装修费
+ 设备费
+ 首批物料
+ 证照办理
+ 开业营销
+ 招聘培训
+ 备用现金
+ 其他启动成本
```

### 月营业额

```txt
月营业额 = 日均订单数 × 客单价 × 月营业天数
```

### 月毛利

```txt
月毛利 = 月营业额 × 综合毛利率
```

### 月固定成本

```txt
月固定成本 =
房租
+ 人工工资
+ 水电燃气基础费用
+ 系统费
+ 管理费
+ 固定营销预算
+ 其他固定支出
```

### 月变动成本

```txt
月变动成本 = 月营业额 × 变动成本率
```

### 月净利润

```txt
月净利润 = 月营业额 - 月变动成本 - 月固定成本
```

### 日均保本营业额

```txt
日均保本营业额 = 月固定成本 ÷ 月营业天数 ÷ 贡献毛利率
```

### 日均保本订单数

```txt
日均保本订单数 = 日均保本营业额 ÷ 客单价
```

### 回本周期

```txt
如果月净利润 > 0：
回本周期 = 初始投资总额 ÷ 月净利润

如果月净利润 ≤ 0：
显示：无法回本
```

### 现金流安全月数

```txt
如果月净利润 < 0：
现金流安全月数 = 可用备用现金 ÷ 月亏损额

如果月净利润 ≥ 0：
显示：当前模型下不消耗备用现金
```

## 9.4 情境模拟

必须有三种默认情境：

```txt
保守情境：
- 日均订单数 -30%
- 客单价 -10%
- 毛利率 -5 个百分点
- 装修费 +15%
- 营销费 +20%

中性情境：
- 使用用户当前输入

乐观情境：
- 日均订单数 +20%
- 客单价 +5%
- 毛利率 +3 个百分点
```

还要支持手动压力测试：

```txt
客流下降 20%
房租上涨 15%
平台抽佣增加 5 个百分点
人工增加 1 人
毛利率下降 5 个百分点
装修超支 20%
开业前三个月营业额只有预期 60%
```

## 11.1 模块定位

```txt
复购订单

```

```txt

是否达到日保本营业额
距离保本线差多少
今日毛利率
今日净利润估算

```

## 11.4 运营诊断规则

示例规则：

```txt
如果营业额 < 日保本营业额：
提示：今日未达保本线，需要分析是订单数不足还是客单价不足。

如果订单数正常但利润低：
提示：可能是毛利率、折扣、平台抽佣或损耗问题。

如果订单数低但客单价正常：
提示：重点检查门头转化、活动触达、外卖曝光和老客复购。

如果客单价低：
提示：优化套餐结构、加购项、组合销售。

如果外卖占比高但利润低：
提示：检查平台抽佣、满减活动和配送补贴是否吞噬利润。

如果差评增加：
提示：优先排查出餐速度、产品稳定性和服务问题。
```

## 11.5 下一步动作建议

系统输出不要泛泛而谈，要像运营主管一样明确：

```txt
下一步动作：

1. 本周先不要继续加大投流，因为当前平台订单毛利偏低。
2. 优先测试 2 个高毛利套餐，把客单价从 26 元拉到 31 元。
3. 晚高峰排班从 3 人调整为 2 人，观察人工占比变化。
4. 对最近 7 天差评做分类，确认是口味、速度还是包装问题。
5. 建立老客复购券，不要继续依赖新客满减。
```

# 16. UI/UX 设计方向

## 16.1 整体气质

不要做成“创业激情工具”，要做成“冷静的商业判断系统”。

视觉关键词：

```txt
冷静
专业
克制
可信
结构化
有判断力
有压力感
不花哨
不幼稚
不营销
```

## 16.2 页面风格

可以参考：

- Linear 的克制信息结构
- Notion 的清晰层级
- Apple 风格的留白和卡片
- 咨询报告式的风险摘要
- 财务仪表盘式的指标表达

不要参考：

- 夸张渐变 SaaS 落地页
- 加盟招商网站
- 游戏化创业页面
- 太可爱的插画风
- 大面积霓虹科技风

## 16.3 组件系统

# 18. 开店后运营系统补强：从“开业”到“盈利”的闭环

> 这一章是对原方案的重点补强。前面的“加盟分析”和“投资测算”解决的是开店前能不能投、该不该签、风险在哪里；但一个真实门店的死亡，往往不是死在签约当天，而是死在开业后的日常经营偏差里：营业额没有达到保本线、毛利被活动和损耗吃掉、人工排班失控、复购起不来、差评积累、库存周转慢、外卖平台越做越亏。

所以产品必须从“加盟前风控工具”升级为“开店后经营操作系统”。开店后的模块不能只是每日流水记录，而要覆盖：

```txt
收入增长
成本控制
毛利管理
库存损耗
人员排班
外卖平台
会员复购
产品菜单
客户评价
现金流预警
运营动作复盘
```

开店后的核心判断不再是“这个项目看起来赚钱吗”，而是：

> 今天、这周、这个月的经营结果，是否正在验证或推翻当初的投资假设？

---

## 18.1 开店后运营的总模型

开店后的经营驾驶舱建议拆成 8 个子系统：

```txt
1. 营业额与订单结构
2. 利润与保本监控
3. 成本与毛利控制
4. 菜单与产品结构
5. 客流与转化
6. 会员与复购
7. 库存与损耗
8. 人员与排班
```

这 8 个子系统共同回答 4 个问题：

```txt
1. 有没有收入？
2. 收入有没有利润？
3. 利润是否可持续？
4. 如果不可持续，优先改哪里？
```

产品不要只给用户一个“今日营业额 ¥3,280”。这个数字本身没有意义。真正有意义的是：

```txt
今日营业额 ¥3,280
日保本营业额 ¥4,150
距离保本线 -¥870
主要原因：订单数低于预期 21%，客单价正常，毛利率低于模型 4.8 个百分点
建议动作：先排查外卖活动折扣和损耗，不要盲目加投流
```

---

## 18.2 子系统一：营业额与订单结构

### 模块目标

判断门店今天的收入问题到底来自哪里：

```txt
订单数不够？
客单价不够？
堂食弱？
外卖弱？
高峰时段没吃满？
周末和工作日结构不对？
```

### 每日输入

```ts
type RevenueDailyInput = {
  date: string
  totalRevenue: number
  totalOrders: number
  averageOrderValue: number
  dineInRevenue: number
  deliveryRevenue: number
  dineInOrders: number
  deliveryOrders: number
  morningRevenue: number
  lunchRevenue: number
  afternoonRevenue: number
  dinnerRevenue: number
  lateNightRevenue: number
}
```

### 核心计算

```txt
客单价 = 总营业额 ÷ 总订单数
堂食占比 = 堂食营业额 ÷ 总营业额
外卖占比 = 外卖营业额 ÷ 总营业额
午高峰贡献 = 午高峰营业额 ÷ 总营业额
晚高峰贡献 = 晚高峰营业额 ÷ 总营业额
订单达成率 = 实际订单数 ÷ 目标订单数
营业额达成率 = 实际营业额 ÷ 目标营业额
```

### 诊断规则

```txt
如果营业额低、订单数低、客单价正常：
说明问题主要是流量和转化，不是定价。
建议检查门头、外卖曝光、活动触达、地段真实人流。

如果营业额低、订单数正常、客单价低：
说明问题主要是产品组合和加购能力。
建议优化套餐、加价购、小食/饮品搭配、高毛利组合。

如果堂食弱、外卖强：
说明门店位置自然转化弱，过度依赖平台。
建议检查门头可见度、附近人流、堂食体验、是否需要调整门店定位。

如果外卖强但利润低：
说明平台抽佣、满减、配送补贴可能吞掉利润。
建议单独核算外卖净利，不要只看外卖流水。

如果午高峰强、晚高峰弱：
适合写字楼、学校、办公区品类；晚间不要盲目加人手。

如果下午茶强、正餐弱：
产品可能更偏轻饮/甜品/休闲，需要重新设计时段运营策略。
```

### 页面输出

```txt
今日营业额：¥3,280
目标营业额：¥4,150
达成率：79%

订单数：112 单
目标订单数：145 单
订单达成率：77%

客单价：¥29.3
目标客单价：¥28.5
判断：客单价达标，问题主要在订单数。

收入结构：
- 堂食：38%
- 外卖：62%

系统判断：
当前门店不是“卖得便宜”，而是“来的人不够”。优先解决流量和转化，不要先涨价。
```

## 18.3 子系统二：利润与保本监控

### 模块目标

很多小店老板只看营业额，不看利润。产品必须每天提醒：

> 今天不是卖了多少钱，而是有没有越卖越亏。

### 每日输入

```ts
type ProfitDailyInput = {
  revenue: number
  materialCost: number
  packagingCost: number
  platformCommission: number
  deliverySubsidy: number
  discountCost: number
  laborCostAllocated: number
  rentAllocated: number
  utilitiesAllocated: number
  marketingCost: number
  lossAmount: number
}
```

### 核心计算

```txt
日毛利 = 营业额 - 原材料成本 - 包装成本 - 平台抽佣 - 配送补贴 - 活动折扣 - 损耗
日毛利率 = 日毛利 ÷ 营业额
日固定成本摊销 = 月固定成本 ÷ 月营业天数
日净利润 = 日毛利 - 日固定成本摊销 - 当日营销费用
日保本营业额 = 月固定成本 ÷ 月营业天数 ÷ 贡献毛利率
距离保本线 = 今日营业额 - 日保本营业额
```

### 诊断规则

```txt
如果营业额高但净利润低：
优先检查毛利率、平台抽佣、满减活动、损耗。

如果营业额低但毛利率健康：
说明成本结构暂时没坏，优先解决订单数。

如果连续 3 天低于保本线：
触发黄色预警。

如果连续 7 天低于保本线：
触发红色预警，要求用户重估月度现金流。

如果日净利润为负但营业额达标：
说明收入结构有问题，可能是低毛利产品卖得太多，或活动力度过大。
```

### 页面输出

```txt
今日利润判断：未达保本线

今日营业额：¥3,280
日保本营业额：¥4,150
距离保本线：-¥870

今日毛利率：48.2%
模型毛利率：53.0%
偏差：-4.8 个百分点

今日净利润估算：-¥426

系统判断：
今天不是单纯“营业额不够”，还存在毛利率偏低。建议先检查外卖满减、原材料损耗和低毛利产品占比。
```

## 18.4 子系统三：成本与毛利控制

### 模块目标

开店后的核心不是“每天多卖一点”，而是防止三类成本失控：

```txt
1. 原材料 / 货品成本
2. 人工成本
3. 房租与固定成本
```

餐饮经营里常用 prime cost 来看核心成本，即 COGS 加人工成本；不少行业资料会把 prime cost 控制在约 60%-65% 销售额附近作为参考，但这个值会随品类、服务模式和城市变化，不应该硬编码成绝对红线。

### 输入字段

```ts
type CostControlInput = {
  revenue: number
  cogs: number
  laborCost: number
  rent: number
  utilities: number
  platformFees: number
  marketing: number
  waste: number
}
```

### 核心计算

```txt
COGS率 = 原材料/货品成本 ÷ 营业额
人工成本率 = 人工成本 ÷ 营业额
房租成本率 = 房租摊销 ÷ 营业额
Prime Cost = COGS + 人工成本
Prime Cost率 = Prime Cost ÷ 营业额
平台费用率 = 平台抽佣与补贴 ÷ 外卖营业额
营销费用率 = 营销费用 ÷ 营业额
损耗率 = 损耗金额 ÷ 营业额
```

### 诊断规则

```txt
如果 COGS率上升：
检查采购价、配方标准、出品克重、报损、员工餐、偷损。

如果人工成本率上升：
检查排班是否与高峰匹配，低峰是否人手过多。

如果房租成本率上升：
本质通常不是房租变贵，而是营业额不足。

如果平台费用率上升：
检查满减、配送补贴、平台活动、佣金规则。

如果 Prime Cost率过高：
说明原材料和人工已经吞掉大部分收入，必须优先处理菜单毛利或排班。
```

## 18.5 子系统四：菜单与产品结构

### 模块目标

很多门店不是“没有爆品”，而是产品结构不健康：

```txt
高销量但低毛利
高毛利但没人买
菜单太复杂导致备货和出餐压力
活动款卖太多吞掉利润
没有加购项导致客单价拉不起来
```

### 产品级输入

```ts
type MenuItemPerformance = {
  id: string
  name: string
  category: string
  price: number
  unitCost: number
  grossMargin: number
  unitsSold: number
  revenue: number
  grossProfit: number
  prepComplexity: 'low' | 'medium' | 'high'
  isPromotionItem: boolean
}
```

### 核心计算

```txt
单品毛利 = 售价 - 单位成本
单品毛利率 = 单品毛利 ÷ 售价
单品销售额贡献 = 单品销售额 ÷ 总营业额
单品毛利贡献 = 单品毛利额 ÷ 总毛利额
销量排名
毛利额排名
```

### 四象限分类

```txt
明星品：高销量 + 高毛利
引流品：高销量 + 低毛利
潜力品：低销量 + 高毛利
淘汰品：低销量 + 低毛利
```

### 系统动作建议

```txt
明星品：
放在菜单核心位置，做套餐主推。

引流品：
控制活动力度，必须搭配高毛利加购项。

潜力品：
通过套餐、推荐语、陈列、员工话术提升曝光。

淘汰品：
减少备货，评估下架，降低库存复杂度。
```

### 页面输出示例

```txt
产品结构诊断：不健康

问题：销量最高的 3 个产品中，有 2 个毛利率低于 35%。
影响：营业额看起来不错，但利润被低毛利产品吃掉。

建议：
1. 把 A 产品从单品促销改成套餐加购。
2. 将 B 产品和高毛利小食组合。
3. C 产品销量低且毛利低，建议减少备货或下架。
```

## 18.6 子系统五：客流与转化

### 模块目标

门店收入 = 人流 × 进店率 × 成交率 × 客单价。

开店后不能只看结果，要拆前端漏斗：

```txt
经过多少人？
多少人停下？
多少人进店？
多少人购买？
多少人复购？
```

### 输入字段

```ts
type TrafficFunnelInput = {
  passbyCount: number
  stopCount: number
  enterStoreCount: number
  purchaseCount: number
  newCustomerCount: number
  repeatCustomerCount: number
}
```

### 核心计算

```txt
停留率 = 停下人数 ÷ 经过人数
进店率 = 进店人数 ÷ 经过人数
成交率 = 购买人数 ÷ 进店人数
复购占比 = 复购订单 ÷ 总订单
```

### 诊断规则

```txt
人流高、进店低：
门头、品类表达、价格带、陈列、门口动线有问题。

进店高、成交低：
产品吸引力、价格、菜单表达、服务话术有问题。

成交正常、复购低：
产品稳定性、会员机制、体验记忆点有问题。

人流低、外卖也低：
选址本身可能不成立，需要重新审视点位。
```

## 18.7 子系统六：会员与复购

### 模块目标

新店前期靠流量，后期靠复购。产品必须让用户知道：

> 这家店有没有从“一次性尝鲜”变成“稳定消费习惯”。

### 输入字段

```ts
type RetentionInput = {
  newCustomers: number
  returningCustomers: number
  membersAdded: number
  memberOrders: number
  couponsIssued: number
  couponsRedeemed: number
  repeatOrders7d: number
  repeatOrders30d: number
}
```

### 核心计算

```txt
复购率 = 复购客户数 ÷ 总客户数
会员转化率 = 新增会员 ÷ 新客户数
会员订单占比 = 会员订单 ÷ 总订单
券核销率 = 已核销优惠券 ÷ 已发放优惠券
7日复购率 = 7日内复购客户 ÷ 新客户数
30日复购率 = 30日内复购客户 ÷ 新客户数
```

### 诊断规则

```txt
新客多、复购低：
说明尝鲜有吸引力，但产品或体验没有形成习惯。

会员多、会员订单少：
说明会员机制只是收集手机号，没有真实激励。

发券多、核销低：
说明优惠券设计不对，可能门槛过高或场景不明确。

复购高但客单价低：
可以通过会员套餐、储值、组合购提升客单价。
```

## 18.8 子系统七：库存与损耗

### 模块目标

小店利润经常死在库存和损耗里，尤其是餐饮、烘焙、生鲜、茶饮、咖啡、小吃。

系统要监控：

```txt
采购是否过量
库存是否积压
临期是否增加
报损是否异常
理论用量和实际用量是否偏离
```

### 输入字段

```ts
type InventoryInput = {
  sku: string
  beginningInventory: number
  purchases: number
  theoreticalUsage: number
  actualUsage: number
  endingInventory: number
  wasteAmount: number
  expiredAmount: number
  stockoutCount: number
}
```

### 核心计算

```txt
实际耗用 = 期初库存 + 本期采购 - 期末库存
耗用偏差 = 实际耗用 - 理论耗用
损耗率 = 报损金额 ÷ 营业额
库存周转天数 = 平均库存 ÷ 日均耗用
缺货次数
临期金额
```

### 诊断规则

```txt
实际耗用 > 理论耗用：
可能存在出品克重不稳定、报损漏记、员工操作浪费、偷损。

库存周转天数过长：
说明采购过量或销量预测错误。

频繁缺货：
说明备货模型不足，会影响爆品销售和用户体验。

临期金额增加：
说明菜单结构或采购节奏有问题。
```

## 18.9 子系统八：人员与排班

### 模块目标

人工成本不是越低越好，而是要和营业时段、订单峰值、出餐压力匹配。

### 输入字段

```ts
type LaborInput = {
  date: string
  laborHours: number
  laborCost: number
  revenue: number
  orders: number
  peakHourOrders: number
  staffCountByHour: Record<string, number>
}
```

### 核心计算

```txt
人工成本率 = 人工成本 ÷ 营业额
人效 = 营业额 ÷ 人工小时
单人小时订单数 = 订单数 ÷ 人工小时
高峰人力负载 = 高峰订单数 ÷ 高峰人数
```

### 诊断规则

```txt
人工成本率高、人效低：
低峰时段排班过重。

高峰差评多、人效过高：
不是效率高，而是人手不够导致体验下降。

订单波动大但排班固定：
需要按时段排班，而不是按全天固定人数。

外卖高峰与堂食高峰重叠：
需要设置打包岗/出餐岗分工。
```

```txt
第四行行动建议：
今天先改什么 / 本周重点动作 / 不建议做什么

右侧：

```

示例文案：

```txt
今日经营判断：黄色预警

你今天没有达到保本线，但不是所有指标都坏。

主要问题：
1. 订单数低于目标 23%
2. 毛利率低于模型 4.8 个百分点
3. 外卖占比达到 64%，但外卖净利率偏低

暂时不要做：
- 不要直接加大满减活动
- 不要盲目延长营业时间
- 不要继续增加低毛利引流品

优先做：
1. 明天拆分堂食和外卖净利
2. 检查 TOP 10 产品毛利贡献
3. 把晚高峰排班从 3 人调整为 2 人测试 3 天
4. 设计一个高毛利套餐替代现有满减
```

## 18.11 开店后风险规则

运营风险应该自动进入 Risk Register。

```txt
连续 3 天低于日保本营业额：
风险等级：中高
建议动作：拆分订单数、客单价、毛利率，确认主要偏差来源。

连续 7 天低于日保本营业额：
风险等级：高
建议动作：重估月度现金流，暂停新增投入。

毛利率连续 5 天低于模型 5 个百分点：
风险等级：高
建议动作：检查采购价、损耗、活动折扣、低毛利产品占比。

外卖流水增长但外卖净利下降：
风险等级：中高
建议动作：单独核算平台活动，不再用总流水判断外卖效果。

人工成本率连续 7 天高于目标：
风险等级：中
建议动作：按时段重排班，低峰减人，高峰保体验。

库存损耗率连续上升：
风险等级：中高
建议动作：检查备货、临期、报损和出品标准。

差评连续 3 天增加：
风险等级：中高
建议动作：按口味、速度、服务、包装、漏单分类处理。

复购率低于目标：
风险等级：中
建议动作：设计二次到店理由，而不是继续只拉新。
```

## 18.12 开店后行动库 Action Playbook

系统不要只输出“建议优化运营”，而要有可执行动作库。

### 收入不足动作

```txt
问题：订单数不足
动作：
1. 连续 3 天记录门口经过人数、停留人数、进店人数。
2. 检查门头 5 秒内是否能看懂卖什么、多少钱、适合谁。
3. 外卖平台检查曝光、进店、下单三个转化率。
4. 先做小范围套餐测试，不直接大额投流。
```

### 客单价不足动作

```txt
问题：客单价低
动作：
1. 增加高毛利加购项。
2. 把单品促销改为套餐组合。
3. 设计 3 档价格锚点：基础款、推荐款、高毛利款。
4. 员工话术从“要不要加”改为“推荐搭配”。
```

### 毛利不足动作

```txt
问题：毛利率低
动作：
1. 拉出销量 TOP 20 单品毛利表。
2. 找出高销量低毛利引流品。
3. 减少低毛利产品活动曝光。
4. 检查实际出品克重和理论配方是否一致。
5. 复核总部供货价或供应商采购价。
```

### 人工过高动作

```txt
问题：人工成本率高
动作：
1. 按小时统计订单，不按全天平均排班。
2. 低峰减少固定岗，高峰保留关键岗。
3. 区分堂食岗、外卖打包岗、出餐岗。
4. 连续 7 天跟踪人效：营业额 ÷ 人工小时。
```

### 外卖亏损动作

```txt
问题：外卖流水高但利润低
动作：
1. 单独计算外卖净利，不看总流水。
2. 拆分平台佣金、满减、配送补贴、包装成本。
3. 下架低毛利外卖活动款。
4. 设计外卖专属高毛利套餐。
5. 设置最低起送价和合理满减门槛。
```

### 复购不足动作

```txt
问题：复购低
动作：
1. 不要只发无差别优惠券。
2. 按首次购买产品设计二次推荐。
3. 建立 7 日复购券和 30 日唤醒券。
4. 对高频客户设计储值或会员权益。
5. 追踪券核销率，而不是只看发券数量。
```

# 19. 最终产品判断标准

这个产品做完后，不能只是“看起来有页面”。

它必须达到这几个标准：

1. 用户能录入一个真实加盟项目。
2. 系统能识别品牌方常见风险。
3. 用户能算出真实保本订单数。
4. 用户能看到保守情境下是否会亏死。
5. 用户能判断某个选址是否值得蹲点。
6. 开店后用户能每天记录经营数据。
7. 系统能告诉用户今天哪里偏离预期。
8. 所有风险能进入统一风险清单。
9. 首页能明确告诉用户当前最大风险。
10. 整体界面像一个专业决策系统，而不是玩具 Demo。

最核心的一句话：

> **这个产品不是帮助用户更快开店，而是帮助用户少踩坑、少冲动、少被话术带着走；如果项目真的可行，再帮助他持续经营到盈利。**
