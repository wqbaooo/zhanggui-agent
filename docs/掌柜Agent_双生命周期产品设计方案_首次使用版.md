# 掌柜Agent｜双生命周期产品设计方案（首次使用版）

> 版本：V1.0  
> 用途：发给 Gemini / 前端设计 Agent / OpenCode，用于设计掌柜Agent的首页与信息架构  
> 设计前提：**第一次使用，没有任何真实数据，不使用模拟数据。**  
> 核心目标：先让用户理解产品、创建项目、看懂两个生命周期，再逐步补数据。

---

## 1. 产品一句话定义

**掌柜Agent 是一个围绕餐饮加盟开店项目的“双生命周期总控台”。**

它把两个阶段连接起来：

1. **开店前生命周期**：加盟调研、资料搜集、资金测算、选址验证、签约准备。
2. **开店后生命周期**：门店经营、财务现金流、外卖利润、库存排班、复购增长、总部兑现。

产品不是单纯的“加盟避坑工具”，也不是普通“门店运营看板”。

它的核心价值是：

> 让普通餐饮加盟创业者，在开店前能看清项目，在开店后能持续经营，不把前期判断和后期运营割裂。

---

## 2. 设计基调

### 2.1 不要做成什么

不要做成：

- 传统 SaaS 后台；
- 满屏表格的经营系统；
- 黑科技大屏；
- 三栏式任务工作台；
- “不适合加盟 / 不建议加盟”到处乱跳的风险工具；
- 一上来就展示一堆假数据的 Demo 页面；
- 超级加盟商用的多品牌管理平台。

### 2.2 应该做成什么

应该做成：

> 像给投资人、合伙人、自己看的“餐饮开店项目总览网站”。

用户第一次打开时，不应该看到一堆空洞指标，而应该看到：

- 这个产品能帮我管理什么；
- 我的开店项目会经历哪两个生命周期；
- 我现在应该先创建什么；
- 哪些数据后面会变成开店后的经营基准；
- 总部协作为什么会贯穿前后两个阶段；
- 下一步怎么开始。

---

## 3. 用户画像与使用场景

### 3.1 用户不是超级加盟商

用户不是同时比较几十个品牌的专业投资人，也不是连锁管理公司。

用户更可能是：

- 第一次或少数几次开餐饮店；
- 已经有一个现实加盟项目；
- 预算有限；
- 时间有限；
- 不想研究复杂行业术语；
- 只想知道项目现在是否清楚、钱是否够、总部是否配合、开业后怎么别亏。

### 3.2 第一次使用的真实心理

第一次进入产品时，用户还没有录入数据。

这时不要显示虚假的：

- 今日营业额；
- 外卖订单；
- 现金安全月数；
- 总部兑现率；
- 风险分数。

这些都应该是空状态。

第一次使用的首页应该回答：

1. 掌柜Agent 是做什么的？
2. 我应该先建一个什么项目？
3. 开店前和开店后分别会管理什么？
4. 哪些内容现在就可以开始填？
5. 哪些模块会在开业后自动启用？

---

## 4. 核心产品结构：一个项目，两条生命周期

掌柜Agent 的最高层信息结构是：

```txt
掌柜Agent
└── 我的餐饮开店项目
    ├── 开店前生命周期
    │   ├── 情报搜集
    │   ├── 加盟资料
    │   ├── 资金测算
    │   ├── 选址验证
    │   └── 签约准备
    │
    ├── 开店后生命周期
    │   ├── 今日经营
    │   ├── 财务现金流
    │   ├── 外卖利润
    │   ├── 库存排班
    │   ├── 复购增长
    │   └── 总部兑现
    │
    └── 连接层
        ├── 资金与经营模型
        ├── 总部协作与约束
        ├── 经营权限
        ├── 风险清单
        └── AI参谋
```

---

## 5. 两个生命周期的关系

### 5.1 开店前生命周期

开店前的核心不是“吓用户不要加盟”，而是帮助用户把项目从模糊变清楚。

开店前主要管理：

- 外部情报；
- 加盟资料；
- 合同资料；
- 费用结构；
- 总部承诺；
- 资金模型；
- 选址验证；
- 签约准备。

核心问题：

```txt
这个项目是否已经足够清楚，可以继续推进？
```

而不是：

```txt
这个加盟是不是一定靠谱 / 一定不靠谱？
```

### 5.2 开店后生命周期

开店后进入经营期，产品重心从“资料是否清楚”转向“经营是否健康”。

开店后主要管理：

- 每日营业额；
- 订单数；
- 客单价；
- 毛利率；
- Prime Cost；
- 外卖单均利润；
- 库存损耗；
- 排班效率；
- 复购；
- 总部支持兑现。

核心问题：

```txt
这个店今天有没有朝盈利方向走？
```

### 5.3 两个生命周期的连接点

这才是产品的意义。

| 连接点 | 开店前的作用 | 开店后的作用 |
|---|---|---|
| 资金模型 | 判断能不能开、每天要卖多少才不亏 | 变成每日经营基准线 |
| 总部协作 | 确认总部承诺、培训、采购、选址、外卖权限 | 追踪总部是否兑现 |
| 经营权限 | 签约前确认菜单、定价、采购、促销权限 | 过滤门店能不能执行某个运营动作 |
| 风险清单 | 记录签约前资料缺口和假设 | 延续到经营期，记录真实经营风险 |
| AI参谋 | 帮用户理解资料、生成问题、引导录入 | 帮用户解释异常、判断下一步 |

## 6. 首页设计原则

### 6.1 首页是总览，不是功能页

首页第一层只做总览，不做详细功能。

首页负责：

- 让用户理解项目全貌；
- 让用户看到两个生命周期；
- 让用户知道现在该开始录入什么；
- 让用户看到哪些模块未来会被启用；
- 让用户有一个沉浸式、可信、完整的项目入口。

详细测算、合同检查、外卖利润计算、库存分析等，全部放到二级/三级页面。

### 6.2 第一次使用不能展示假数据

没有数据时不要模拟。

所有数据模块都应显示为“等待录入 / 创建项目后生成 / 开业后启用”。

例如：

- 可用现金：待录入；
- 日保本营业额：录入预算与成本后生成；
- 外卖利润：开业后接入或手动录入后生成；
- 总部兑现率：录入总部承诺后生成。

### 6.3 加盟功能要收敛

加盟不是到处乱出现的警告，而是收敛到两个位置：

1. **开店前生命周期**：加盟资料、合同资料、签约准备。
2. **总部协作与约束**：采购、培训、外卖代运营、区域保护、权限。

首页不要到处写：

```txt
不适合加盟 / 不建议加盟 / 高风险加盟
```

应该写：

```txt
资料待补齐 / 总部协作待确认 / 开店前准备未完成
```

---

## 7. 首页信息架构

首页建议按以下顺序设计：

```txt
1. 项目总览 Hero
2. 首次使用引导区
3. 双生命周期地图
4. 今日餐饮与加盟情报入口
5. 我的项目 / 店铺入口
6. 资金与经营模型入口
7. 总部协作与约束入口
8. 关键事项与下一步
9. AI参谋入口
```

# 8. 首页模块详细方案

## 8.1 模块一：项目总览 Hero

### 目标

让用户一进入产品，就感觉这是一个“餐饮开店项目总览系统”，不是一个散乱工具箱。

### 首次使用状态

因为没有创建项目，Hero 不显示假数据，而显示创建引导。

### 示例文案

```txt
掌柜Agent
餐饮开店项目总览

从加盟调研、资金测算、选址验证，到开业后的经营、外卖、现金流和总部兑现，掌柜Agent 帮你把开店项目从想法管理到盈利。

你还没有创建项目。
先创建一个餐饮开店项目，系统会自动生成两个生命周期：
开店前：调研与筹备
开店后：经营与盈利
```

### Hero 主要按钮

```txt
[创建我的第一个开店项目]
[先了解产品怎么用]
[导入已有项目资料]
```

### Hero 辅助信息

显示三个价值点：

```txt
1. 开店前：看清加盟资料、费用、选址和资金模型
2. 开店后：持续看经营、外卖、现金流、库存和总部兑现
3. 全程：AI参谋帮你解释信息、生成问题和下一步动作
```

---

## 8.2 模块二：首次使用引导区

### 目标

第一次使用时，页面不能空，也不能造假。应该用引导性空状态告诉用户从哪里开始。

### 结构

```txt
开始使用掌柜Agent，只需要三步：

1. 创建项目
填写项目名称、品类、城市、当前阶段、预算。

2. 补充开店前资料
录入品牌资料、费用结构、总部承诺、选址信息、资金预算。

3. 开业后切换经营模式
记录营业额、外卖、库存、排班、总部支持兑现情况。
```

### 视觉

三张横向步骤卡：

- Step 1：创建项目；
- Step 2：补充资料；
- Step 3：开业后经营。

每张卡有一个明确按钮。

---

## 8.3 模块三：双生命周期地图

### 目标

这是产品核心视觉。

它要让用户一眼理解：

> 掌柜Agent 管的是开店前和开店后两个生命周期。

### 首次使用状态

没有项目时，地图是“空状态地图”。

左侧：开店前生命周期。

```txt
开店前：调研与筹备

情报搜集：创建项目后启用
加盟资料：创建项目后启用
资金测算：录入预算后生成
选址验证：录入铺位后启用
签约准备：补充合同资料后启用
```

右侧：开店后生命周期。

```txt
开店后：经营与盈利

今日经营：开业后启用
财务现金流：开业后启用
外卖利润：开业后启用
库存排班：开业后启用
复购增长：开业后启用
总部兑现：录入总部承诺后追踪
```

### 设计要求

- 左右并列；
- 中间用一条“连接线”表达两个阶段不是割裂的；
- 连接线上的关键节点是：资金模型、总部协作、风险清单；
- 不要使用复杂流程图；
- 要像高级项目路线图。

---

## 8.4 模块四：今日餐饮与加盟情报入口

### 目标

这是外部环境层。

第一次使用时，可以展示空状态或轻量入口，不要模拟新闻。

### 首次使用状态

```txt
今日餐饮与加盟情报

连接城市、品类和品牌后，掌柜Agent 会为你整理：
- 餐饮行业动态
- 加盟品牌动态
- 政策监管提醒
- 本地商圈变化
- 外卖平台趋势

每条情报都会标注：对你的项目有什么影响。
```

### 主要按钮

```txt
[设置关注城市]
[设置关注品类]
[设置关注品牌]
```

### 情报展示原则

未来有数据后，每条情报采用：

```txt
标题
摘要
对我的影响
相关动作
```

不要直接在情报流里插入“是否加盟”的结论。

---

## 8.5 模块五：我的项目 / 店铺入口

### 目标

用户以后可以管理多个项目或门店，但第一次使用时只引导创建第一个项目。

### 首次使用状态

```txt
我的项目

你还没有创建开店项目。
创建后，这里会显示你的主项目、备选项目和未来开业门店。

示例项目类型：
- 正在调研的加盟项目
- 正在筹备的门店
- 已开业的门店
- 备选项目
```

### 按钮

```txt
[创建主项目]
[添加备选项目]
```

### 有项目后的卡片字段

```txt
项目名称
生命周期：开店前 / 开店后
阶段：看品牌 / 谈加盟 / 选址 / 装修 / 试营业 / 经营中
当前状态
下一步
点击进入项目详情
```

## 8.6 模块六：资金与经营模型入口

### 目标

这是开店前与开店后的核心连接点。

第一次使用时，不显示假金额，显示“需要哪些数据才能生成模型”。

### 首次使用状态

```txt
资金与经营模型

录入预算和成本后，系统会生成：
- 预计总投入
- 月固定成本
- 日保本营业额
- 日保本订单数
- 回本周期
- 现金流安全月数

开业后，这些数据会变成每日经营基准线。
```

### 需要用户录入的数据

```txt
预算
加盟费
保证金
装修设备
首批物料
月租金
人工
客单价
毛利率
备用现金
```

### 按钮

```txt
[开始建立资金模型]
```

---

## 8.7 模块七：总部协作与约束入口

### 目标

这是加盟功能的核心承载区，不要再散落到各个模块。

### 首次使用状态

```txt
总部协作与约束

加盟店和独立店不一样。
很多经营动作会受到总部合同、SOP、采购、菜单、定价和外卖权限影响。

录入总部承诺后，系统会帮你追踪：
- 签约前是否写清
- 开业后是否兑现
- 对经营动作有没有限制
```

### 需要记录的内容

```txt
采购价目表
培训安排
选址支持
开业督导
外卖代运营
区域保护
定价权限
促销权限
菜单权限
供应链稳定
问题响应
```

### 按钮

```txt
[录入总部协作事项]
```

---

## 8.8 模块八：关键事项与下一步

### 目标

第一次使用时，这个模块不能显示假风险，而是显示“开始建议”。

### 首次使用状态

```txt
关键事项与下一步

当前还没有项目数据。
建议先完成：
1. 创建第一个开店项目
2. 选择当前阶段
3. 录入预算和总部资料

完成后，系统会自动生成：
- 开店前必须处理的事项
- 开业后需要持续关注的事项
- 今天最重要的 3 个动作
```

### 有数据后的结构

```txt
开店前必须处理
开店后持续关注
今天下一步
```

风险只在这里集中收口，不要散落到各个模块里。

---

## 8.9 模块九：AI 参谋入口

### 目标

AI 是引导，不是主页面。

第一次使用时，AI 应该帮助用户创建项目，而不是泛泛聊天。

### 推荐入口

- 顶部输入框；
- 右下角轻量浮层；
- 首页 Hero 中的“问掌柜”。

### 首次使用提示语

```txt
你可以直接告诉我：
- 我准备加盟一个奶茶品牌，预算 45 万
- 我现在正在谈加盟，还没签约
- 我已经签了，准备找铺位
- 我已经开业，想看今天赚没赚

我会帮你创建项目，并生成对应生命周期。
```

### AI 输入示例

```txt
我准备加盟一家奶茶店，预算 45 万，计划 7 月开业。
```

AI 输出不应该只是一段文字，而应该引导创建项目：

```txt
我会为你创建一个“餐饮加盟开店项目”。
当前生命周期：开店前。
建议先补充：品类、城市、品牌名称、预算、当前阶段。

[创建项目]
```

# 9. 二级页面规划

## 9.1 项目详情页

进入条件：用户创建项目后。

页面结构：

```txt
顶部：项目名称 / 生命周期 / 阶段 / 状态
左侧：项目阶段时间线
中间：当前阶段详情
右侧：AI建议 / 关键事项
```

内容：

- 项目基础信息；
- 当前阶段；
- 资料完整度；
- 资金模型摘要；
- 总部协作摘要；
- 下一步动作。

---

## 9.2 开店前详情页

承载：

- 情报搜集；
- 加盟资料；
- 合同资料；
- 资金测算；
- 选址验证；
- 签约准备。

---

## 9.3 开店后详情页

承载：

- 今日经营；
- 财务现金流；
- 外卖利润；
- 库存损耗；
- 人员排班；
- 复购增长；
- 总部兑现。

首次使用时，这些可以显示为“开业后启用”。

## 9.4 资金模型详情页

## 9.6 风险与下一步详情页

- AI解释。

# 10. 首次使用的页面状态设计

## 10.1 总体原则

没有数据时，页面不能空，也不能造假。

每个模块都应该显示：

```txt
这个模块未来会帮你做什么
需要你先提供什么
点击哪里开始
```

## 10.2 空状态类型

### 类型一：等待创建项目

用于首页 Hero、我的项目。

文案：

```txt
你还没有创建开店项目。
创建后，系统会生成开店前和开店后两个生命周期。
```

### 类型二：等待录入资料

用于资金模型、总部协作。

文案：

```txt
录入基础数据后，这里会生成你的项目模型。
```

### 类型三：开业后启用

用于经营、外卖、库存、排班、复购。

文案：

```txt
开业后，这里会自动切换为经营追踪。
```

### 类型四：等待关注设置

用于餐饮加盟情报。

文案：

```txt
设置城市、品类和品牌后，系统会整理与你项目相关的情报。
```

# 11. 首次使用流程

## Step 1：进入首页

看到：

- 产品定义；
- 两个生命周期说明；
- 创建项目入口；
- AI 引导。

## Step 2：创建项目

表单字段：

```txt
项目名称
品类
城市
当前阶段
目标开业时间
预算
是否已经确定品牌
是否已经签约
是否已经有铺位
```

## Step 3：系统生成项目骨架

生成：

- 开店前生命周期；
- 开店后生命周期；
- 空的资金模型；
- 空的总部协作清单；
- 初始下一步清单。

## Step 4：用户逐步补资料

不强迫一次填完。

允许从这些入口开始：

- 先填预算；
- 先填品牌资料；
- 先填总部承诺；
- 先填选址；
- 先问 AI。

# 12. 视觉设计要求

## 12.1 视觉关键词

```txt
沉浸式
项目总览
投资人视角
餐饮经营感
温和可信
有层次
模块清晰
不焦虑
```

## 12.2 色彩建议

```txt
背景：奶油白 / 暖灰
主色：深墨绿
辅助：米色、浅金、暖灰
状态色：
- 绿色：已完成 / 可推进
- 黄色：待确认 / 待补充
- 红色：真正阻塞
- 蓝色：信息提示
```

## 12.3 布局建议

首页采用长页面沉浸式模块布局：

```txt
大 Hero
首次使用引导
双生命周期地图
信息入口模块
连接层模块
下一步模块
AI 浮层
```

不要一上来使用三栏。

三栏可以用于二级详情页。

## 12.4 字体与质感

- 中文字体清晰优先；
- 标题大而稳；
- 卡片要有层次；
- 不要大面积纯黑；
- 不要炫酷霓虹；
- 不要太像普通后台。

# 13. 给前端 / Gemini 的执行提示词

以下内容可以直接复制给 Gemini 或前端设计 Agent：

```txt
请为“掌柜Agent”设计一个首次使用状态下的产品首页。

注意：不要使用模拟数据，不要展示虚假的营业额、现金流、外卖订单、风险评分。

产品定位：
掌柜Agent 是餐饮加盟开店项目的全生命周期总控台。
它连接两个生命周期：
1. 开店前：加盟调研、资料搜集、资金测算、选址验证、签约准备。
2. 开店后：门店经营、财务现金流、外卖利润、库存排班、复购增长、总部兑现。

用户不是超级加盟商，不需要一上来看到复杂的加盟风险分析。
用户第一次进入产品时，应该一眼看懂：
- 这个产品能帮我管理什么；
- 开店前和开店后分别包含什么；
- 我应该先创建一个项目；
- 哪些模块现在需要录入资料；
- 哪些模块开业后才启用。

首页必须是沉浸式信息总览，不是三栏式工作台。

页面结构：

1. 项目总览 Hero
首次使用状态：显示产品定义和创建项目入口。
文案方向：
“从加盟调研、资金测算、选址验证，到开业后的经营、外卖、现金流和总部兑现，掌柜Agent 帮你把开店项目从想法管理到盈利。”
按钮：
- 创建我的第一个开店项目
- 先了解产品怎么用
- 导入已有资料

2. 首次使用引导区
三步：
- 创建项目
- 补充开店前资料
- 开业后切换经营模式

3. 双生命周期地图
左右两个大区块：
左侧：开店前生命周期
- 情报搜集
- 加盟资料
- 资金测算
- 选址验证
- 签约准备
状态显示：创建项目后启用 / 待录入 / 待验证

右侧：开店后生命周期
- 今日经营
- 财务现金流
- 外卖利润
- 库存排班
- 复购增长
- 总部兑现
状态显示：开业后启用 / 录入总部承诺后追踪

中间强调连接层：
- 资金模型
- 总部协作
- 风险清单
- AI参谋

4. 今日餐饮与加盟情报入口
首次使用状态：提示用户设置关注城市、品类、品牌。
不要模拟新闻。

5. 我的项目 / 店铺入口
首次使用状态：提示还没有创建项目。
按钮：创建主项目 / 添加备选项目。

6. 资金与经营模型入口
首次使用状态：说明录入预算和成本后会生成：
- 预计总投入
- 月固定成本
- 日保本营业额
- 日保本订单数
- 回本周期
- 现金流安全月数
并说明：开业后这些数据会成为每日经营基准线。

7. 总部协作与约束入口
说明加盟店和独立店不同，很多动作会受总部合同、采购、定价、菜单、外卖权限影响。
需要记录：采购价目表、培训、选址支持、开业督导、外卖代运营、区域保护、定价权限、促销权限。

8. 关键事项与下一步
首次使用状态：
当前还没有项目数据。
建议先完成：
- 创建第一个开店项目
- 选择当前阶段
- 录入预算和总部资料

9. AI参谋入口
AI不要占据主页面。
它应该作为顶部输入框或右下角轻量浮层。
首次提示语：
“你可以直接告诉我：我准备加盟一家奶茶店，预算45万，计划7月开业。”

视觉要求：
- 沉浸式
- 项目总览感
- 像投资人/合伙人能一眼看懂的项目主页
- 奶油白背景
- 深墨绿品牌色
- 卡片有层次
- 不要黑科技大屏
- 不要传统后台
- 不要三栏首页
- 不要到处出现不适合加盟/不要加盟
- 没有数据时必须使用空状态和引导，不要造假
```

# 14. 最终总结

掌柜Agent 的首页不是“已有数据的大盘”，而是：

> 首次使用时，帮助用户理解产品、创建项目、建立双生命周期骨架；有数据后，逐步变成项目总览、经营总览和风险总览。

它的产品骨架是：

```txt
一个餐饮开店项目
两条生命周期
三个连接层
一个AI参谋
```

两条生命周期：

```txt
开店前：调研与筹备
开店后：经营与盈利
```

三个连接层：

```txt
资金模型
总部协作
风险清单
```

一个 AI 参谋：

```txt
解释、引导、生成问题、帮助用户进入下一步。
```

这才是掌柜Agent的完整产品形态。
