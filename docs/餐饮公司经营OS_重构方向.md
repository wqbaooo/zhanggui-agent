# 餐饮公司经营 OS：重构方向

## 一句话目标

掌柜Agent 不是聊天工具，也不是静态看板，而是把一家小餐饮公司的关键部门合成一个经营系统：

- 老板室：每天判断主要矛盾、取舍和止损线。
- 财务部：看流水、真实利润、现金流、回本和成本结构。
- 外卖渠道诊断：从商家侧看美团/淘宝闪购/抖音等渠道的曝光转化、评价、满减、套餐和单均利润。
- 门店运营部：看排班、出餐、损耗、复购、会员和服务稳定性。
- 市场部：结合天气、节假日、平台活动和本地竞品做营销计划。
- 风控部：记录风险、验证假设、追踪合同/加盟承诺兑现。

## 不能承诺的事

系统不能承诺“保证盈利”。能做的是建立持续经营纪律：

1. 每天录入或接入真实经营数据。
2. 每天判断利润、现金流和外卖单均利润。
3. 每周复盘平台活动、差评、菜单和排班。
4. 每月更新成本、现金安全月和止损线。

目标是提高持续盈利概率，及时发现亏损信号，避免靠感觉经营。

## 外卖渠道接入路线

边界：掌柜Agent 不做外卖平台，不做骑手调度，不替代美团/淘宝闪购/抖音。它只做商家侧经营诊断，把平台后台里的数据变成老板能执行的动作。

### 第 1 层：笨办法接入

先支持复制粘贴、CSV、截图 OCR：

- 美团商家后台日报
- 淘宝闪购订单/评价摘要
- 抖音本地生活团购/核销数据

先解析这些字段：

- 曝光、进店、下单、核销、复购
- 营业额、订单数、客单价
- 平台费、佣金、满减、补贴、包装费
- 评分、差评、评价关键词

### 第 2 层：开放平台 API

等具备资质后接：

- 美团外卖：门店、商品、评价、活动、订单、订单推送、退款推送
- 淘宝闪购：订单、评价、退款、状态推送
- 抖音生活服务：门店、团购套餐、核销、POI、达人/内容相关数据

### 第 3 层：统一外卖渠道经营模型

所有平台数据统一成：

- platform_metrics
- delivery_funnel
- reviews
- order_items
- promotion_costs
- action_tasks

然后输出：

- 外卖单均利润
- 满减是否亏钱
- 平台佣金压力
- 曝光到下单的转化短板
- 差评根因
- 今日运营动作

## 天气、节假日和本地事件

天气和节假日不是装饰，它们影响：

- 备货量
- 排班
- 外卖/堂食比例
- 热饮/冷饮/小吃结构
- 营销活动
- 商圈人流

后续应增加经营日历：

- 法定节假日
- 周末/工作日
- 天气
- 本地活动
- 平台大促
- 学校开学/放假

## 页面结构原则

下拉菜单必须对应真实页面，不做无意义锚点。

每个页面必须有：

1. 当前判断
2. 关键指标
3. 数据来源
4. 风险/异常
5. 下一步动作
6. 可录入或可接入的数据入口
