## 2. 当前产品判断

当前正确方向：

```text
餐饮接店经营贾维斯
用户输入一句话 / 上传截图 / 复制平台日报
  -> 掌柜总控 Agent 理解意图
  -> 分派给部门 Agent
  -> 各 Agent 查数据、算账、判断风险、预测明天
  -> 汇总成老板能执行的方案
  -> 写入门店档案，持续监测和复盘
```

产品不是：
- 不是外卖平台
- 不是普通 POS
- 不是开店准备百科
- 不是静态 dashboard
- 不是简单课程列表

产品应该像：
- AI 版支付宝的入口逻辑：对话主入口 + 少数高频动作 + 动态服务卡
- 餐饮公司经营 OS：财务、外卖、评价、风控、地图、天气、库存、排班、行业情报共同工作

## 4. 当前存在的明显问题

2. 顶部导航仍然太多。用户希望像 AI 版支付宝一样极简。

6. 数据记录、异常检测、预测、建议闭环还没有统一在一个总控界面。
7. AI 对话还没有真正“分派 Agent -> 生成结果卡 -> 写入档案”。

## 7. 高德、天气、节假日如何放

不要恢复“开店准备”。

高德地图应作为 `地图商圈 Agent`：
- 周边竞品密度
- 学校/社区/写字楼/商场/医院
- 停车和交通
- 新增竞品提醒
- 商圈客流假设

天气节假日应作为 `天气节假日 Agent`：
- 明天雨天/高温/低温
- 周末和节假日
- 商场活动
- 对堂食/外卖比例的影响
- 对备货和排班的建议

示例输出：

```text
明天周六小雨：
- 堂食预计 -12%
- 外卖预计 +18%
- 热食套餐备货 +15%
- 冷饮低频品减少 10%
- 午高峰多 1 人，晚高峰不加人
```

## 10. 注意事项

1. 用户明确不喜欢形式主义导航，不要做按钮但不跳转的菜单。
2. 用户希望为了价值可以重构，不要畏手畏脚保留旧页面。
3. 用户当前阶段是“准备接店”，不是“找铺开店”。
4. “教学”不要做死板课程，要做情境化教学：系统发现问题时才教。
5. 所有建议都要能落到：
   - 数据依据
   - 风险
   - 下一步动作
   - 如何验证
6. AI 时代感来自：
   - 对话主导
   - 多 Agent 分工
   - 动态生成结果卡
   - 记录和预测
   - 主动异常提醒
