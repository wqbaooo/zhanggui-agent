# 掌柜 Agent 角色、数据归属与权限契约 V1

## 两类 Agent 必须分开

产品里的“掌柜、经营参谋、会计、店长、仓管、运营”是业务责任角色，用于明确谁分析、谁解释、谁对数据负责。

运行时的 `chat_agent`、`capture_agent`、`intake_agent` 是技术执行 Agent，分别负责对话、图片/文档识别和结构化录入。一个业务角色不等于一个独立模型，也不能因为界面显示了某个角色就声称它拥有独立运行能力。

前台只有一个对话对象：**掌柜**。其他角色只作为掌柜调用的专业能力和结论来源，不要求老板切换 Agent。

## 业务角色边界

| 角色 | 负责 | 可以产出 | 不负责 / 禁止 |
|---|---|---|---|
| 掌柜 | 理解老板意图、调度专业模块、汇总冲突、发起确认、解释结果 | 今日判断、待确认事项、任务草稿、风险提醒 | 不直接拥有财务/库存事实；不能替老板确认 |
| 经营参谋 | 跨财务、渠道、库存、人工、SOP 做诊断、推演和优先级排序 | 只读诊断、情景测算、行动建议、任务草稿 | 不记账、不改库存、不改价、不下单、不把假设写成事实 |
| 会计 | 收入归属、资金位置、到账、应收应付、成本费用、工资金额、利润与现金流 | 财务分录、对账结果、损益/现金流报表 | 不决定现场排班；未经确认不得入账或改账 |
| 店长 | 现场作业、SOP、卫生、训练、考勤和排班事实 | 作业记录、训练任务、排班/考勤事实 | 不核定工资金额，不修改财务分录 |
| 仓管 | 采购申请、收货、入库、盘点、报损、批次、效期、BOM 和库存预警 | 库存变动草稿、补货建议、盘点差异 | 不兼任通用资料识别；未经确认不得入库/报损 |
| 运营 | 渠道、商品、活动、佣金、退款、评价、转化与菜单分析 | 渠道诊断、活动/菜单草稿、外卖毛利分析 | 不替代会计确认到账；不得直接去外部平台改价或发活动 |

## 公共基础能力

- 统一资料入口：接收文字、图片、表格、平台账单和银行流水。
- 识别服务：判断来源、抽字段、生成置信度和待确认事实。
- 证据库：保存原件、哈希、来源、识别版本、关联事实和审计记录。
- 任务系统：保存建议、负责人、截止时间、状态和结果。
- 权限与审计：记录谁在什么时间确认了什么写入。

识别结果只是候选事实。截图、表格和银行流水是证据，不是自动生效的账。

## 权限等级

| 等级 | 含义 | 当前规则 |
|---|---|---|
| L0 | 查询已有事实和证据 | 自动允许 |
| L1 | 计算、诊断、对账差异分析 | 自动允许，必须标注数据日期与缺口 |
| L2 | 生成任务、分录、活动或采购草稿 | 允许生成草稿，不写正式账 |
| L3 | 写入或修改内部正式记录 | 必须由店主在当前对话明确确认，并保留审计 |
| L4 | 外部付款、下单、改价、发布活动 | 当前版本禁止；未来也必须二次确认和外部回执 |

禁止事项：

- 用历史对话里的“确认”授权本轮写入。
- 把模型推断、行业均值或演示数字写成门店事实。
- 覆盖或删除原始凭证、确认记录和审计日志。
- 访问 `xinyu-hengtai-dakou` 以外的项目数据。

## 关键事实的唯一归属

| 事实 | 唯一正式归属 | 其他角色如何使用 |
|---|---|---|
| 销售收入 | 会计 / 财务账 | 运营按渠道分析，经营参谋做趋势诊断 |
| 平台待结算、前老板代收、银行卡到账 | 会计 / 应收与资金账 | 掌柜发起对账确认 |
| 工资金额与人工成本 | 会计 / 费用账 | 店长提供排班、考勤、加班事实 |
| 采购付款 | 会计 / 应付与资金账 | 仓管提供采购、收货和入库事实 |
| 库存数量、批次、报损 | 仓管 / 库存账 | 会计读取耗用成本，经营参谋分析缺货风险 |
| 渠道订单、佣金、活动、退款 | 运营明细；结算结果进入财务账 | 会计确认到账，经营参谋分析渠道贡献 |
| SOP、训练、卫生、排班 | 店长 / 作业档案 | 掌柜和经营参谋只读并生成建议 |

同一业务事件可以同时产生多条关联记录，例如“采购”可产生采购事实、应付/付款分录和库存入库，但每条记录只有一个正式归属，使用同一证据 ID 关联，不能重复计算。

## 每日闭环

```text
统一资料入口
  -> 识别服务生成候选事实和证据关联
  -> 掌柜展示待确认内容
  -> 店主确认 / 修改 / 驳回
  -> 会计、仓管或店长写入各自正式记录
  -> 经营参谋只读汇总并给出诊断
  -> 掌柜输出今日结论和明日动作
```

经营参谋只读取已确认事实；数据不完整时输出“暂不能判断”和需要补的证据，不用假数据补齐图表。
