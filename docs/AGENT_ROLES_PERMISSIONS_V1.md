# 掌柜 Agent 角色、数据归属与权限契约 V1

## 业务 Agent 与执行能力必须分开

产品里的“掌柜、经营参谋、会计、店长、仓管、运营”是业务责任角色，用于明确谁分析、谁解释、谁对数据负责。

运行时的 `capture_agent`、`intake_agent` 等是可被各业务 Agent 调用的技术执行能力，分别负责图片/文档识别和结构化录入。财务、库存等业务 Agent 可以是真实独立运行的专业 Agent，但必须明确声明自己的工具白名单、RAG 范围、会话范围和写入权限。

掌柜 Agent 是全店总协调者，财务、库存、店务和运营界面可以有各自独立的专业 Agent 对话。老板在哪个模块打开对话，就是在和该模块真实 Agent 交流；跨模块问题可以交给掌柜协调，也可以通过明示交接在专业 Agent 之间流转。

### 独立但联系的运行契约

- 会话隔离：每个 Agent 使用独立 `scope` 保存历史，不把总 Agent 的全部对话原样注入。
- 专业隔离：每个 Agent 只能调用自己的事实、计算与草稿工具。
- 交接有据：跨模块时传递问题摘要、必要证据 ID、期间和所需结果，不宣称尚未执行的 Agent 已经完成任务。
- 记忆可解释：只记录老板重复关注的主题和最近时间，用于调整展示优先级，不虚构心理特征。

### 模型、运行时与 Skills

财务 Agent 采用“产品后端守事实，DeepSeek 负责理解和推理”的结构。实现吸收两类开源 Agent 模式，但不让第三方框架接管账本或权限：

- Hermes 模式：技能目录只先暴露名称和用途，Agent 需要时才选择具体技能；会话事实与可复用流程分开保存。
- Pi 模式：模型根据当前目标和多轮上下文选择只读工具，读取结果后再组织回答；每次调用都经过工具白名单。
- 产品自有闭环：路由、会话、财务 Skills、台账查询、事实校验、权限和审计均由本项目运行时执行。

财务 Agent 当前注册的专业 Skills 包括：逐日账目完整性、资金位置追踪、利润完整性、经营指标分析、凭证证据审计、平台结算与应收对账。Skills 只提供专业流程，不拥有数据；所有金额、日期、状态和证据仍以正式台账为准。

边界约束的是动作，不是思考：L0/L1 的跨模块已确认事实可读取和分析；L2 只能生成草稿；L3/L4 必须确认或禁止。不得再用“当前句子是否含财务关键词”阻断多轮上下文中的正常分析。

### 上下级与任务闭环

- 掌柜 Agent 是上级协调者：接收全店目标、拆分跨模块任务、跟踪交接与汇总结果，但不绕过专业 Agent 改写其正式账。
- 财务 Agent 是财务域负责人：可以独立完成查询、核算、对账、识别、生成执行方案、等待确认、正式入账和结果回读；对财务正式记录拥有唯一执行入口。
- 库存、运营、店务 Agent 是并列专业角色：可把采购、渠道、排班等已确认事实交给财务核算，但不能直接写财务账；财务也不能替它们改库存、排班或 SOP。
- 每次交接必须包含目标、期间、必要事实或证据、期望输出和状态；`suggested` 只表示建议，`queued_for_master` 只表示已交给总 Agent 调度，两者都不能伪装成目标 Agent 已接受或已完成。

财务任务闭环固定为：`理解目标 -> 获取必要事实 -> 调用专业 Skill -> 生成执行方案 -> 老板当前会话确认 -> 财务 Agent 执行 -> 回读正式记录 -> 更新台账/分析/待办`。确认之前不会写正式账，确认之后不能只回复成功而不核对持久化结果。

## 业务角色边界

| 角色 | 负责 | 可以产出 | 不负责 / 禁止 |
|---|---|---|---|
| 掌柜 | 理解老板意图、调度专业模块、汇总冲突、发起确认、解释结果 | 今日判断、待确认事项、任务草稿、风险提醒 | 不直接拥有财务/库存事实；不能替老板确认 |
| 经营参谋 | 跨财务、渠道、库存、人工、SOP 做诊断、推演和优先级排序 | 只读诊断、情景测算、行动建议、任务草稿 | 不记账、不改库存、不改价、不下单、不把假设写成事实 |
| 会计 | 收入归属、资金位置、到账、应收应付、成本费用、工资金额、利润与现金流 | 财务分录、对账结果、损益/现金流报表 | 不决定现场排班；未经确认不得入账或改账 |
| 店长 | 现场作业、SOP、卫生、训练、考勤和排班事实 | 作业记录、训练任务、排班/考勤事实 | 不核定工资金额，不修改财务分录 |
| 仓管 | 采购申请、收货、入库、盘点、报损、批次、效期、BOM 和库存预警 | 库存变动草稿、补货建议、盘点差异 | 不兼任通用资料识别；未经确认不得入库/报损 |
| 运营 | 渠道、商品、活动、佣金、退款、评价、转化与菜单分析 | 渠道诊断、活动/菜单草稿、外卖毛利分析 | 不替代会计确认到账；不得直接去外部平台改价或发活动 |

## 公共基础能力

- 统一资料入口：接收文字、图片、表格、平台账单和银行流水。
- 识别服务：判断来源、抽字段、生成置信度和待确认事实。
- 证据库：保存原件、哈希、来源、识别版本、关联事实和审计记录。
- 任务系统：保存建议、负责人、截止时间、状态和结果。
- 权限与审计：记录谁在什么时间确认了什么写入。

识别结果只是候选事实。截图、表格和银行流水是证据，不是自动生效的账。

## 权限等级

| 等级 | 含义 | 当前规则 |
|---|---|---|
| L0 | 查询已有事实和证据 | 自动允许 |
| L1 | 计算、诊断、对账差异分析 | 自动允许，必须标注数据日期与缺口 |
| L2 | 生成任务、分录、活动或采购草稿 | 允许生成草稿，不写正式账 |
| L3 | 写入或修改内部正式记录 | 必须由店主在当前对话明确确认，并保留审计 |
| L4 | 外部付款、下单、改价、发布活动 | 当前版本禁止；未来也必须二次确认和外部回执 |

禁止事项：

- 用历史对话里的“确认”授权本轮写入。
- 把模型推断、行业均值或演示数字写成门店事实。
- 覆盖或删除原始凭证、确认记录和审计日志。
- 访问 `xinyu-hengtai-dakou` 以外的项目数据。

## 关键事实的唯一归属

| 事实 | 唯一正式归属 | 其他角色如何使用 |
|---|---|---|
| 销售收入 | 会计 / 财务账 | 运营按渠道分析，经营参谋做趋势诊断 |
| 平台待结算、前老板代收、银行卡到账 | 会计 / 应收与资金账 | 掌柜发起对账确认 |
| 工资金额与人工成本 | 会计 / 费用账 | 店长提供排班、考勤、加班事实 |
| 采购付款 | 会计 / 应付与资金账 | 仓管提供采购、收货和入库事实 |
| 库存数量、批次、报损 | 仓管 / 库存账 | 会计读取耗用成本，经营参谋分析缺货风险 |
| 渠道订单、佣金、活动、退款 | 运营明细；结算结果进入财务账 | 会计确认到账，经营参谋分析渠道贡献 |
| SOP、训练、卫生、排班 | 店长 / 作业档案 | 掌柜和经营参谋只读并生成建议 |

同一业务事件可以同时产生多条关联记录，例如“采购”可产生采购事实、应付/付款分录和库存入库，但每条记录只有一个正式归属，使用同一证据 ID 关联，不能重复计算。

## 每日闭环

```text
统一资料入口
  -> 识别服务生成候选事实和证据关联
  -> 掌柜展示待确认内容
  -> 店主确认 / 修改 / 驳回
  -> 会计、仓管或店长写入各自正式记录
  -> 经营参谋只读汇总并给出诊断
  -> 掌柜输出今日结论和明日动作
```

经营参谋只读取已确认事实；数据不完整时输出“暂不能判断”和需要补的证据，不用假数据补齐图表。
